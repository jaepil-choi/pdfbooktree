## 변경 배경

- 기존 흐름은 Markdown 분할에 사용할 북마크 레벨과 PDF에 임베드하는 북마크 레벨을 독립적으로 처리했다. 그 결과 Markdown이 길이 제한을 만족하도록 상위 레벨을 선택해도 PDF에는 더 깊은 레벨이 남을 수 있었다.
- OCR overlay 배치 결과를 후속 처리할 때 별도의 북마크 PDF를 복사본으로 만드는 대신, OCR text layer가 포함된 입력 PDF에 북마크만 안전하게 덮어쓸 필요가 있었다.
- 기본 설정만 사용해도 길이 제한 Markdown이 생성되어야 하므로 Markdown 분할 기본값을 활성화하고 `10,000`단어와 `95%` 페이지 커버리지를 기본 제약으로 명시했다.

## 결정 내용

- Markdown을 먼저 내보내 `chosen_level`을 결정하고, PDF에는 전체 계획 중 `level <= chosen_level`인 항목만 임베드한다.
- 전체 추론 결과와 실제 적용 결과를 각각 `bookmark_plan_full.json`과 `bookmark_plan.json`으로 보존한다. 검토 가능한 원본 계획을 잃지 않으면서 최종 PDF와 기본 계획 artifact의 의미를 일치시키기 위한 결정이다.
- `process`, `apply`, `batch` CLI와 대응 Python API에 `in_place` 옵션을 추가했다. 이 옵션은 기존 기본 동작을 바꾸지 않으며 명시적으로 선택한 경우에만 입력 PDF를 교체한다.
- in-place 저장은 입력 PDF 옆 임시 파일에 먼저 기록한 후 페이지 수와 outline을 검증하고 `os.replace`로 교체한다. 실패하면 임시 파일을 제거하고 원본은 유지한다.
- `pdf_overwrite.json`에 교체 전후 SHA-256을 기록하고, batch 결과에는 덮어쓴 PDF 수를 별도로 집계한다.

## 작동 방식

- 기본 Markdown 설정은 `enabled=true`, `max_words=10000`, `coverage_target=0.95`다.
- 처리 파이프라인은 전체 북마크 계획을 검증한 뒤 레벨별 Markdown 분할을 평가하고 제약을 만족하는 `chosen_level`을 선택한다.
- 선택된 레벨 이하의 항목만 유효 계획으로 만들어 PDF outline과 `bookmark_plan.json`에 사용한다. 전체 계획은 별도 artifact로 유지한다.
- in-place 모드에서는 임시 PDF의 페이지 수와 PyMuPDF TOC가 기대값과 정확히 일치해야만 원본 경로로 교체한다.
- 교체가 끝나면 Markdown manifest의 입력 해시를 최종 PDF 해시로 갱신해 artifact 간 해시 관계를 일치시킨다.
- 페이지 번호는 기존 공개 계약과 동일하게 1부터 시작한다.

## 대안과 제외한 선택지

- 전체 계획을 PDF에 임베드한 뒤 Markdown만 상위 레벨로 분할하는 방식은 PDF와 Markdown의 탐색 계층이 달라지는 기존 문제를 유지하므로 제외했다.
- 입력 PDF에 직접 저장하는 방식은 저장 도중 실패하면 파일이 손상될 수 있으므로 제외하고, 검증된 임시 파일의 원자적 교체 방식을 사용했다.
- 전체 계획을 유효 계획으로 덮어쓰는 방식은 추론 결과의 검토 가능성을 잃으므로 전체 계획 artifact를 별도로 보존했다.
- `in_place`를 무조건 기본값으로 만드는 방식은 기존 사용자의 출력 파일 기대를 깨뜨릴 수 있으므로 명시적 옵션으로 유지했다.

## 남은 리스크

- 원자적 교체의 보장 범위는 같은 파일시스템에서 `os.replace`가 제공하는 수준이다. 네트워크 드라이브나 특수 파일시스템에서는 운영체제별 동작을 추가 검증해야 한다.
- 샘플 OCR PDF의 북마크 계획에는 OCR 깨짐이나 본문 문장을 제목으로 오인한 항목이 포함됐다. 레벨 동기화와 저장 안전성은 검증됐지만 북마크 추론 품질은 별도의 개선 대상이다.
- 사용자가 명시적으로 in-place 모드를 선택하면 원본 PDF 복사본을 자동 보존하지 않는다. 복구가 필요한 운영 환경에서는 실행 전 별도 백업 정책이 필요하다.
