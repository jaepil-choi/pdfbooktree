## 결정 내용

- OCR은 resolved input/output 경로가 같으면 `force`와 관계없이 거부하고, 같은 디렉터리의 임시 PDF를 완전히 저장한 뒤 `os.replace`로 교체한다.
- process batch, OCR batch, classify는 `utils.pdf_discovery`의 탐색 규칙을 공유한다. `.pdf` 판정과 glob 비교는 대소문자를 구분하지 않고, 상대 POSIX 경로로 결정적 정렬하며, exclude가 include보다 우선한다.
- 공개 함수 `validate_plan(input_pdf, plan)`과 `apply --dry-run`을 추가했다. dry-run은 입력과 plan을 검증하고 hash와 예상 결과만 반환하며 run directory나 artifact를 쓰지 않는다.
- `ProcessingLogEvent`와 `ProcessingLogger` 프로토콜을 중심으로 rich, plain, JSONL, none logger를 제공한다. `auto`는 TTY일 때만 rich를 선택해 기존 비대화형 무출력 동작을 보존한다.
- 처리 실패 결과에는 실제로 존재하는 artifact 경로만 남긴다. 예정 경로를 성공 결과처럼 반환하지 않는다.
- wheel smoke test는 외부 입력이 없어도 설치된 PyMuPDF로 결정적 2-page PDF를 생성하고, 설치된 CLI의 process와 inspect 결과 및 Markdown graph 무결성을 검증한다.

## 작동 방식

- OCR builder는 설정 타입과 범위를 선검증하고 동일 경로를 차단한다. overlay 저장이 끝난 임시 파일만 목적지로 원자 교체하므로 저장 실패 시 원본과 기존 출력이 유지된다.
- 디렉터리 명령은 공통 탐색기에 input/output과 재귀·glob 설정을 전달한다. output이 input 아래면 해당 subtree를 제외하고, 두 디렉터리가 같으면 입력 오류로 처리한다. manifest에는 필터, 제외 경로, 발견 파일을 기록한다.
- plan 검증은 PDF page count를 직접 읽고 빈 plan, page 범위, level jump를 검사한다. CLI는 JSON·타입 오류를 exit 2 `invalid_plan`, 의미 오류를 exit 3 `processing_failed`, 유효 결과를 exit 0으로 반환하며 실제 apply 직전에도 같은 검증을 반복한다.
- processor는 outline 확인, 분석·페이지 진행, 추론, artifact 작성, apply, 실패·종료 이벤트를 순서대로 발생시킨다. JSON progress는 stderr JSONL에만 쓰고 최종 result envelope는 stdout에만 쓴다.
- Markdown graph 검증은 exporter가 생성한 front matter 링크를 검증 대상으로 삼아 본문 예시의 `[[...]]`를 dangling link로 오인하지 않는다.

## 대안과 제외한 선택지

- 목적지 파일을 먼저 삭제하는 방식은 저장 실패 시 기존 출력까지 잃으므로 배제하고 `os.replace`를 선택했다.
- 각 batch 명령에 독립 탐색 코드를 유지하는 방식은 대소문자, 정렬, output 제외 계약이 다시 갈라지므로 공통 탐색기로 통합했다.
- dry-run에서 run directory를 먼저 만드는 방식은 무쓰기 계약을 깨므로 검증 결과를 메모리에서 구성한다.
- 진행 로그를 기본 활성화하는 방식은 기존 자동화의 stdout/stderr 계약을 바꾸므로 비TTY `auto`를 조용하게 유지했다.
- 분석 cache, interrupted batch resume/retry/jobs, OCR 병렬화와 호출 비용 추정은 릴리스 안전성보다 운영 최적화에 가까워 이번 커밋에서 제외했다.

## 남은 리스크

- GitHub Actions의 Windows/Linux 원격 실행은 push 전이므로 아직 확인하지 않았다.
- atomic replacement는 목적지와 같은 디렉터리에 임시 파일을 만들지만, 파일 시스템과 보안 제품별 `os.replace` 동작 차이는 원격 환경에서 추가 확인이 필요하다.
- 긴 작업은 진행 상태를 제공하지만 중단 후 재개, 재시도, 작업 병렬도 제어는 후속 버전 범위다.
