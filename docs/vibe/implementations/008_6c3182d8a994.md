## 변경 배경

- `detect-bookmark-toc`가 점수 기반으로 TOC page range를 고른 뒤 일부 bookmark title이 range 밖에 남는 문제가 있었다.
- bookmark가 있는 PDF에서 생성하는 TOC page dataset은 기존 bookmark 목록을 기준 정답 신호로 쓰므로, 최종 정답 page range는 사용 가능한 bookmark match를 모두 포함해야 한다.
- OCR noise나 ligature 변형이 있을 수 있어 포함 여부는 정확한 문자열 비교가 아니라 기존 fuzzy matching 결과를 기준으로 판단해야 한다.

## 결정 내용

- 기존 공개 CLI와 결과 모델은 바꾸지 않고 `detect_toc_pages_from_bookmarks` 내부 후처리만 추가했다.
- 점수 기반 segment 선택과 soft edge 확장을 먼저 수행한 뒤, 선택된 page range 안에 없는 bookmark order가 있으면 전체 match evidence에서 해당 bookmark의 page를 찾아 range를 확장한다.
- 누락 bookmark에 대한 후보 match가 여러 개이면 현재 선택 range에 가장 가까운 page를 우선하고, 거리가 같으면 fuzzy score가 높은 match를 선택한다.
- OCR noise를 더 허용하기 위해 bookmark title fuzzy match threshold를 `88.0`에서 `80.0`으로 낮췄다.

## 작동 방식

- 모든 page 번호는 기존 규칙대로 1-based PDF page 번호로 유지한다.
- `match_bookmarks_to_pages`는 page line window와 정규화된 bookmark title을 `rapidfuzz` 점수로 비교해 page별 match evidence와 전체 match 목록을 만든다.
- `expand_pages_to_cover_bookmark_matches`는 선택된 TOC page set 안에 포함된 `bookmark_order`를 계산하고, 사용 가능한 bookmark order 중 빠진 항목을 찾는다.
- 빠진 bookmark의 fuzzy match가 관측된 경우 해당 page를 필수 page로 추가한 뒤, 필수 page의 최소값부터 최대값까지를 최종 연속 range로 반환한다.
- 빠진 bookmark에 대한 match 자체가 관측되지 않은 경우에는 가짜 page를 만들지 않고 기존 range를 유지한다.

## 대안과 제외한 선택지

- segment 선택 단계에서 모든 bookmark를 hard constraint로 넣는 방식은 제외했다. 기존 feature vote와 offset consistency의 역할을 크게 흔들 수 있고, 어떤 bookmark가 OCR 때문에 match되지 않았는지 구분하기 어려웠다.
- 정확한 문자열 포함 검사는 제외했다. TOC text 추출에서는 OCR noise, 특수문자, ligature, 점선 leader, page number suffix 때문에 false negative가 쉽게 발생한다.
- 누락 page만 비연속적으로 추가하는 방식은 제외했다. TOC page label은 range 성격이 강하므로 필수 page의 최소-최대 구간을 연속 page로 유지하는 쪽이 dataset 생성에 더 단순하다.

## 남은 리스크

- threshold를 `80.0`으로 낮추면서 일반 본문에 같은 제목이 반복되는 PDF에서는 match 후보가 늘 수 있다. 다만 누락 bookmark 보완에서는 선택 range와 가까운 page를 우선하므로 먼 본문 page가 바로 선택될 가능성은 낮췄다.
- 어떤 bookmark도 fuzzy match되지 않는 경우에는 반드시 포함 조건을 완전히 만족시킬 수 없다. 이 경우는 별도 진단 필드나 warning으로 드러내는 후속 개선이 필요할 수 있다.
- 실제 대량 dataset 재생성 후 확장된 range가 과도하게 넓어지는 PDF가 있는지 확인해야 한다.
