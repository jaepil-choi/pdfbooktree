## 변경 배경

기존 OCR overlay 구현은 PDF 각 페이지를 300dpi PNG로 렌더링한 뒤 그 이미지 위에 invisible text layer를 붙여 새 PDF를 만들었다. 이 방식은 검색 가능한 PDF를 만들 수는 있지만, 원본 PDF의 이미지 압축과 page content를 버리기 때문에 출력 파일 크기가 크게 증가했다.

실험 `060_preserve_original_pdf_ocr_layer`에서는 원본 PDF에 새 invisible layer만 추가하면 파일 크기는 크게 줄지만 기존 추출 텍스트와 새 OCR 텍스트가 중복되는 문제가 확인됐다. 실험 `064_interest_economics_strip_text_overlay`에서는 원본 PDF에서 기존 text object를 제거한 뒤 새 invisible OCR layer만 얹으면 렌더링은 유지하면서 sandwich PDF보다 훨씬 작은 출력이 가능함을 확인했다. 이번 구현은 그 성공 경로를 `src/`의 public OCR overlay 경로로 옮긴 것이다.

## 결정 내용

- `write_overlay_pdf`의 입력을 `page_images`가 아니라 `source_pdf`로 바꿨다.
- 최종 PDF 생성은 더 이상 ocrmypdf의 `Fpdf2PdfRenderer`로 page image PDF를 합치는 방식이 아니다.
- `pikepdf.parse_content_stream`으로 overwrite 대상 page의 `BT...ET` text object를 제거하고, PyMuPDF `TextWriter.write_text(..., render_mode=3)`로 새 invisible OCR text를 삽입한다.
- `pages` 옵션으로 일부 page만 처리할 때는 해당 page의 기존 text object만 제거한다. 처리하지 않은 page의 기존 text layer와 원본 content는 유지한다.
- 한글 OCR 텍스트 재추출을 위해 Windows 기본 `malgun.ttf`를 우선 사용하고, 없으면 `arial.ttf`, 마지막으로 PyMuPDF 기본 Helvetica로 fallback한다.
- `pikepdf`를 직접 import하게 되었으므로 `pyproject.toml`에 직접 의존성으로 추가했다.

## 작동 방식

`OcrOverlayBuilder`는 OCR engine 입력을 위해 기존처럼 대상 page를 렌더링하고 raw/insertable cache를 만든다. 다만 최종 PDF 조립 단계에서는 렌더링된 PNG 목록을 넘기지 않고 원본 PDF 경로를 넘긴다.

`write_overlay_pdf`는 먼저 임시 `source_text_stripped.pdf`를 만든다. 이 파일은 원본 PDF를 기반으로 하되, insertable page 목록에 포함된 1-based PDF page에서만 content stream의 text object를 제거한 것이다. 이후 PyMuPDF로 stripped PDF를 열고, insertable line bbox를 원본 page point 좌표계로 변환해 line 단위 invisible text를 삽입한다. 출력 저장 시 `garbage=4`, `deflate=True`, `deflate_fonts=True`, `use_objstms=1`, `compression_effort=100`을 사용해 불필요한 객체를 정리하고 압축한다.

## 대안과 제외한 선택지

- 기존 sandwich 방식 유지: 구현은 단순하지만 파일 크기 문제가 커서 제외했다.
- 원본 PDF에 새 invisible layer만 추가: 실험 060에서 기존 text layer와 중복되는 문제가 확인되어 제외했다.
- visible text까지 있는 native PDF에서 text object를 무조건 제거: 화면에 보이는 텍스트까지 사라질 수 있어 안전하지 않다. 이번 구현은 OCR overwrite API의 명시 확인 경로에서 동작하며, showcase에서 렌더 동일성 검증을 별도로 수행한다.
- `insert_textbox(render_mode=3)`: 한글 재추출이 `???`로 깨지는 문제가 있어 실험에서 제외했고, `TextWriter`를 사용했다.

## 남은 리스크

- content stream parsing에 실패한 page는 기존 text object 제거 없이 지나간다. 이런 page에 새 OCR text가 추가되면 중복 텍스트가 남을 수 있으므로, live showcase에서 출력 text와 insertable stats의 비율을 확인한다.
- PDF에 visible text와 OCR text가 함께 있는 경우에는 text object 제거가 화면 픽셀을 바꿀 수 있다. 사용자는 OCR overwrite 대상 PDF를 확인해야 하며, showcase는 샘플 page 렌더 해시로 이를 검증한다.
- `malgun.ttf`가 없는 비Windows 환경에서는 fallback font가 한글 재추출 품질에 영향을 줄 수 있다.
