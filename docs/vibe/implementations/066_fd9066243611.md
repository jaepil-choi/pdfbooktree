- 실험 `106_bookmark_review_evidence_contract.py`에서 요약 → 주의 항목 → 개별 근거 → 원문 페이지로 이어지는 점진적 검토 계약을 실제 PDF로 검증했다.

## 결정 내용

- `bookmark_review_summary.json`과 `bookmark_review_items.jsonl`을 inference artifact로 추가했다. 요약은 저비용 탐색용이고 JSONL은 항목별 선택 조회와 스트리밍에 적합하다.
- 각 검토 항목에 계획 항목, 후보 참조, 대체 후보 참조, 좌표·글꼴·높이 계층, 주변 타이포그래피 줄, 제한된 본문 preview, 원문 근거 참조를 포함했다.
- 동일 source·page·title 후보는 계획 정규화 규칙과 일치하도록 첫 후보를 canonical 후보로 사용하고 나머지는 `candidate_alternative_refs`에 보존했다.
- `inspect plan`에 `--summary`, `--items`, `--limit`, `--item-id`, `--page-range`, `--level`, `--source`, `--attention-only`를 추가하되 인자 없는 기존 동작은 유지했다.
- CLI JSON은 Windows CP949 터미널에서도 실패하지 않도록 ASCII escape를 유지하는 직렬화로 통일했다.
- 저장소 로컬 스킬과 패키지 배포 템플릿의 계약 문서를 같은 커밋에서 동기화했다.

## 작동 방식

- `write_inference_artifacts()`가 정규화된 bookmark plan과 후보, 선택적 입력 PDF·전체 페이지 수·기존 outline을 받아 두 검토 artifact를 생성한다.
- summary는 level/source 분포, 페이지 밀도, 제목·본문 통계와 주의 신호 집계를 제공한다. item은 `item_id`와 `evidence_refs`로 후보 및 원문 페이지에 연결된다.
- 후보 매핑 실패, 낮은 confidence, 중복 후보 축약, 짧거나 긴 제목, 동일 페이지 밀집 등의 신호를 `attention_reasons`로 노출한다.
- 모든 PDF 페이지 번호는 기존 공개 계약과 동일하게 1-based를 사용한다.
- `inspect plan --summary`는 집계만 읽고, `--items`와 필터 조합은 필요한 JSONL 항목만 반환한다. `--item-id`는 단일 항목 조회에 사용한다.
- run manifest에는 `bookmark_review_summary`와 `bookmark_review_items` artifact 역할을 기록해 후속 에이전트가 경로를 재구성하지 않아도 된다.

## 대안과 제외한 선택지

- 모든 근거를 단일 거대 JSON에 넣는 방식은 초기 탐색 비용과 컨텍스트 사용량이 커서 제외했다.
- 후보 중복을 완전히 삭제하는 방식은 대체 근거를 잃으므로 제외하고 canonical 후보와 대체 후보 참조를 분리했다.
- `inspect`에 별도 하위 명령을 추가하는 대신 기존 `inspect plan`을 확장해 호환성과 발견 가능성을 유지했다.
- preview에 원문 전체를 포함하지 않았다. artifact 크기와 민감 정보 노출을 줄이고, 상세 확인은 원문 페이지 참조로 위임했다.

## 남은 리스크

- 현재 주의 신호는 규칙 기반이므로 문서 장르별 false positive가 발생할 수 있다. 실제 검토 결과를 축적해 임계값을 조정해야 한다.
- 이번 showcase는 검토 근거 조회까지 검증했으며, 에이전트가 항목을 수정한 뒤 `apply`까지 수행하는 end-to-end showcase는 남아 있다.
- 이미지 기반 후보처럼 글꼴 정보가 없는 경우 타이포그래피 근거는 제한적이다.
- 릴리스 전 저장소 전체 Ruff baseline 정리와 OCR 배포 정책 확정은 별도 작업이다.
