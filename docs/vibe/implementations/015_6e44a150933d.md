## 변경 배경

- bookmark 기반 pseudo label의 quality를 확인하려고 010~013 실험에서 어떤 PDF가 학습
  소스로 부적합한지 분석했다.
- max_children(과도한 자식 수)나 tree depth 같은 신호는 변별력이 약했다. tree depth는
  101개(약 24%)를 탈락시키는데 그 안에 chapter만 평평하게 bookmark한 정상 책이 많았다.
- 반면 bookmark 제목의 "글자 포함 여부"는 분포가 이중봉으로 깨끗하게 갈렸다. 잘못 들어간
  bookmark는 제목이 `'1'`, `'001'`, `'1110001'`, `'~~0003'`처럼 숫자/기호뿐이었고,
  특히 한국어 OCR 책의 flat 덤프가 이런 형태였다.
- 사용자가 pseudo label 생성 조건을 "page 50 이상 AND 글자 포함 bookmark가 하나라도
  있는 PDF만 포함"으로 확정했다. min page 50은 이미 구현돼 있어 글자 포함 조건만 추가했다.

## 결정 내용

- `pdf/bookmarks.py`에 `title_has_letter(title)`과 `has_letter_bookmark(bookmarks)`
  헬퍼를 추가했다. PDF 포함 여부 판정은 "글자 포함 bookmark가 하나라도 있는가"이므로
  `has_letter_bookmark`는 `any(...)` 의미다.
- 글자 판정은 실험에서 쓴 정규식 `[A-Za-z가-힣]` 대신 `str.isalpha()`로 구현했다.
  숫자/기호뿐인 깨진 제목은 두 방식 모두 동일하게 제외하지만, `isalpha`는 한자 등 다른
  문자 체계의 정상 제목까지 글자로 인정해 비한/영 책의 오탈락을 막는다. "글자 포함"의 가장
  충실한 구현이라 판단했다.
- skip 사유를 기존 `skipped_no_bookmark`, `skipped_short`와 구분해 새 outcome
  `skipped_no_letter`로 분리하고, batch 결과에
  `skipped_no_letter_bookmark_count`를 추가했다. CLI 요약에도 노출했다.

## 작동 방식

- worker `_process_pdf_for_bookmark_toc`는 `total_pages < min_total_pages`면
  `skipped_short`, bookmark가 없으면 `skipped`를 먼저 반환한다. 그다음
  `has_letter_bookmark(bookmarks)`가 False면 `skipped_no_letter`를 반환해 text
  추출과 TOC 탐지 전에 제외한다.
- `_handle_processed_item`은 outcome에 따라
  `(skipped_no_bookmark, skipped_short_pdf, skipped_no_letter)` 3-tuple을 반환하고,
  `run()`이 세 카운터를 누적해 `BookmarkedPdfTocBatchResult`에 담는다.
- 글자 포함 PDF만 기존과 동일하게 bookmark-guided detection과 dataset row 생성을
  거친다. 1-based page convention 등 기존 동작은 바뀌지 않았다.

## 대안과 제외한 선택지

- max_children, tree depth 기반 필터는 제외했다. 변별력이 약하거나(전자 3개) 정상 flat
  책을 대량 오탈락(후자 101개)시켜 pseudo label 분모를 크게 깎는다.
- 개별 bookmark 항목 단위로 숫자/기호 제목만 솎아내는 방식은 채택하지 않았다. 사용자가
  요구한 기준은 PDF 포함/제외 결정이고, 정상 책에 섞인 소수 잡음 bookmark까지 항목 단위로
  제거하면 detection 입력을 예측하기 어렵게 만든다.
- 글자 판정 정규식 `[A-Za-z가-힣]`은 제외했다. 한자 등 다른 문자 책을 오탈락시킬 수 있어
  `str.isalpha()`가 더 안전하다.

## 남은 리스크

- 글자 포함 조건은 "전부 숫자/기호"인 명백한 깨진 케이스만 거른다. 700선 용어집처럼 제목이
  정상 단어지만 책이 아닌 PDF는 여전히 남는다. 이는 bookmarks_per_page 등 별도 신호로
  후속 검토해야 한다.
- 클래스 메서드 `_detect_pdf`는 현재 호출되지 않는 잔존 코드라 글자 필터를 적용하지
  않았다. 실 경로는 worker 함수 `_process_pdf_for_bookmark_toc`다. 추후 이 메서드를
  되살리면 동일 필터를 함께 넣어야 한다.
- `isalpha` 기반 판정은 detection.json 재생성 결과로 검증하지 않았다. 실험(012)에서
  frac_no_letter > 0.5로 잡은 10개와, 실제 "글자 포함 0개" PDF 집합은 약간 다를 수 있다
  (예: 'Blank Page' 한 항목 때문에 frac_no_letter=0.86이던 PDF는 이 구현에서는 포함된다).
