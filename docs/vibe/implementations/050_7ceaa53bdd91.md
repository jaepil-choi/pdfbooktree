## 대안과 제외한 선택지

- JSON 파일 전체를 fixture 파일로 저장해 byte-for-byte snapshot 비교하지 않았다.
  float 값, 임시 경로, warning 문구의 사소한 표현까지 결합되면 의미 없는 snapshot
  갱신이 늘어나므로 field와 shape는 엄격히 고정하되 실행별 값은 의미 단위로 비교했다.
- PDF binary와 Markdown 본문 전체를 golden으로 고정하지 않았다. PDF metadata와
  serializer 차이로 불안정해질 수 있고, 이 단계에서 필요한 계약은 파일 생성 여부,
  이름, plan/report 연결이기 때문이다.
- 실패 exit code 테스트를 새 파일에 복제하지 않았다. 기존
  `test_process_exception은_run_manifest를_failed로_남긴다`가 exception의 exit code 1과
  failed manifest error shape를 이미 고정한다.
- Phase 3 result/error envelope를 함께 구현하지 않았다. 먼저 현재 계약을 고정해야
  다음 변경에서 깨지는 assertion이 의도된 migration인지 회귀인지 판단할 수 있다.

## 남은 리스크

- report JSON의 `report_path=null`과 최종 Python 결과의 실제 report path 사이에
  비대칭이 있다. Phase 3에서 versioned result envelope를 설계할 때 report 자체가
  자기 경로를 포함할지 명시적으로 결정해야 한다.
- `process` CLI stdout은 Rich가 렌더링한 human dict라 안정적인 JSON parser 계약이
  아니다. 이번 테스트는 최상위 key 노출만 고정했고, `--format human|json`, stdout
  final result/stderr progress 분리, 공통 error envelope는 Phase 3에 남아 있다.
- native/OCR 실제 책의 artifact 값 자체는 이 테스트에 포함하지 않았다. algorithm
  또는 extraction artifact의 real-data 회귀가 필요하면 별도 showcase/contract
  점검으로 보완해야 한다.
