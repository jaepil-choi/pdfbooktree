## 변경 배경

- 이 저장소의 목표는 PDF 목차를 디렉터리 트리 + markdown 본문으로 만드는 것이다. PDF에 이미
  bookmark(목차 outline)가 있으면 TOC 탐지/LLM 없이 곧장 트리와 본문을 만들 수 있다.
- 이 "쉬운 경로"를 실험 019(`experiments/019_bookmark_tree_to_markdown_dir.py`)에서 검증했고
  (Hull native, Shreve scanned+OCR 두 권) 사용자가 출력 형태를 승인했다.
- 기존 `Processor.run()`은 bookmark가 있으면 `skip_existing_bookmarks=True`(기본값)에 따라 아무
  것도 하지 않고 `status="skipped"`로 즉시 종료했다. 사용자가 "bookmark가 있으면 skip하지 말고
  markdown export하라. 단 bookmark를 PDF에 embed(overwrite)하는 작업만 건너뛰라"고 요구해
  그 동작을 바꿨다.

## 결정 내용

- 새 config 플래그를 만들지 않고 기존 `skip_existing_bookmarks`의 의미를 "bookmark
  embedding(PDF outline overwrite)을 건너뛸지"로 좁혀 재사용했다. bookmark가 있고 이 플래그가
  켜져 있으면(기본값) markdown을 export하고 embedding만 생략한다. `--no-skip-existing-bookmarks`는
  기존 bookmark를 무시하고 TOC 탐지부터 강제 재처리하는 manual trigger다.
- 책임 분리: 순수 구조 변환은 `toc/bookmark_tree.py`(PyMuPDF 비의존), 파일시스템 writer는
  `output/bookmark_markdown.py`에 두었다. `output/markdown.py`의 `export_markdown_tree`
  스텁은 flat `ContentRange`용이라 트리 형태와 입력이 달라 오버로드하지 않고 별도 모듈로 분리했다.
- 모델: `BookmarkTreeNode`를 frozen dataclass로 추가했다. level stack은 부모 생성 후 자식을
  붙이므로 frozen 노드를 top-down으로 만들 수 없어, mutable builder dict로 트리를 만든 뒤
  post-order로 동결한다. `own_span`(자기 본문 page 구간)을 빌드 시점에 미리 채워 writer가
  page_count를 한 번만 알면 되게 했다.
- 이름 정리는 PoC 방식을 그대로 살린 `sanitize_title_for_path`를 새로 추가했다. 기존
  `safe_filename`은 공백을 `_`로 바꾸는 ASCII 중심이라 승인된 출력 형태("01_1.1 Exchange-Traded
  Markets")를 깨뜨린다. 새 함수는 Windows 금지 문자만 제거하고 공백·Unicode(한글)는 보존한다.
  `safe_filename`은 PDF/report 경로용으로 그대로 둔다.

## 작동 방식

- `Processor.run()`은 `extract_existing_bookmarks` 후 `bookmarks and skip_existing_bookmarks`이면
  `export_bookmark_markdown_tree(input_pdf, output_dir, bookmarks)`를 호출하고
  `status="processed"`, `output_markdown_dir`, `bookmark_count`를 채운 결과를 반환한다. 경고에는
  embedding을 건너뛰고 markdown을 export했다는 사실을 남긴다. 그 외(bookmark 없음, 또는 강제
  재처리)는 기존 TOC 탐지 파이프라인으로 그대로 내려간다.
- `build_bookmark_tree`: reading order로 각 노드의 다음 non-None pdf_page를 찾아 own_span을
  계산한다. own_span = `start ~ 다음 bookmark 시작 page-1`(마지막은 page_count, 빈 구간은 None).
  level stack으로 중첩하고 post-order로 동결한다. None pdf_page bookmark는 경계로 쓰지 않아
  앞 노드 구간이 그 위를 건너뛰어 확장된다.
- `export_bookmark_markdown_tree`: `plan_markdown_dir_path`로 `{stem}_markdown` 루트를 잡고,
  `iter_tree_pages`가 모은 구간 page만 `extract_selected_page_texts`로 한 번에 추출해
  `{pdf_page: text}` map을 만든다. 재귀 `_write_node`가 `NN_<제목>` 디렉터리(NN은 부모 안에서
  1부터 재시작)와 동명 `.md`를 쓴다. 모든 page는 1-based다.
- markdown 본문: `# <제목>\n\n<!-- own page span: S-E -->\n\n` 헤더 뒤에 구간 내 각 page를
  `<!-- pdf_page N -->\n\n<page text(strip)>`로 붙인다. own_span이 None이면 헤더만 남는다.
- rmtree 없이 `mkdir(exist_ok=True)` + 제자리 덮어쓰기로, 열린 폴더에서의 Windows 파일 잠금
  (WinError 32)을 피한다. PoC에 있던 legacy `content.md` 정리 코드는 실험 잔재라 production에는
  넣지 않았다.

## 대안과 제외한 선택지

- 새 `export_existing_bookmarks` config 플래그 추가: 사용자가 "기존 플래그로 manual trigger"를
  요구해 제외하고, `skip_existing_bookmarks` 의미를 좁혀 재사용했다.
- `output/markdown.py`의 `export_markdown_tree` 스텁 오버로드: 입력이 flat `ContentRange`로
  트리와 형태가 달라 제외하고 별도 모듈로 분리했다.
- `safe_filename` 재사용: 공백을 `_`로 바꿔 승인된 출력 형태를 깨뜨려 제외했다.
- frozen 노드에 mutable `children: list` 보유: frozen 일관성을 깨뜨려 제외하고 builder→동결 방식을
  택했다.

## 남은 리스크

- page 단위 슬라이싱이라 절이 page 중간에서 시작하면 그 page의 앞 절 꼬리 텍스트가 섞인다.
  정밀하게 자르려면 bookmark dest 좌표나 block 단위 슬라이싱이 필요하다.
- 강제 재처리(`--no-skip-existing-bookmarks`)는 기존 TOC 탐지/embed 파이프라인으로 내려가며, 이
  경로의 bookmark embedding과 markdown export는 아직 후속 구현 대상이다.
- `BatchProcessor`에는 아직 이 export 동작을 노출하지 않았다(단일 `process` 경로만 반영).
