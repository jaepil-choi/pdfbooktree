## 변경 배경

- `detect-bookmark-toc` 명령은 bookmark 기반으로 `TocPageDatasetRow` JSON/CSV를 생성하지만, 이 dataset을 바로 train/test하는 production 진입점이 없었다.
- 기존 `train-toc-detector`는 `manual_reviewed` label JSON을 입력으로 받고 PDF에서 feature를 다시 추출하는 흐름이라, 이미 생성된 page row dataset의 classifier 성능을 확인하는 요구와 맞지 않았다.
- `outputs/300study_toc_dataset.json`은 310개 PDF, 5225개 row를 포함했고 `bookmark_guided_toc_detection` pseudo label 재현 성능을 빠르게 평가할 필요가 있었다.

## 결정 내용

- 새 CLI `train-toc-page-dataset`을 추가해 `detect-bookmark-toc` 산출물인 JSON/CSV dataset을 직접 학습 입력으로 받게 했다.
- 학습 구현은 `pdfbooktree.toc.dataset_training`에 분리했다. 기존 `toc.training`은 manual review label 기반 detector 학습 책임을 유지하고, 새 모듈은 생성된 page row dataset classifier 학습과 train/test report 저장만 담당한다.
- split은 row random split이 아니라 `input_pdf` 기준 `GroupShuffleSplit`으로 수행한다. 같은 PDF의 page row가 train과 test에 동시에 들어가면 실제 일반화 성능보다 높게 보일 수 있기 때문이다.
- 모델은 `decision-tree`, `hist-gradient`, `random-forest`, `all` 옵션을 제공한다. `all`은 세 모델을 같은 split에서 비교하고 F1, ROC AUC 순으로 best model을 고른다.
- 학습 artifact는 `toc_page_dataset_model.joblib`, 평가 report는 `train_test_report.json`으로 저장한다.

## 작동 방식

- `load_toc_page_dataset_rows`는 row list JSON, `dataset_rows`를 가진 detection result JSON, CSV를 모두 읽는다.
- `validate_dataset_rows`는 `input_pdf`, `label`, feature field 존재 여부와 0/1 label 양쪽 class 포함 여부를 확인한다.
- feature matrix는 `TocPageDatasetRow`의 현재 scalar feature와 previous page feature를 함께 사용한다. boolean은 0/1로 바꾸고, `None`이나 빈 문자열은 `SimpleImputer`에서 0.0으로 채운다.
- `TocPageDatasetTrainer.run`은 PDF group 기준 train/test를 나눈 뒤 지정된 모델을 학습하고 test split 지표를 계산한다.
- report에는 label source, pseudo label 해석 경고, split 정책, row/PDF 수, 모델별 accuracy/precision/recall/F1/ROC AUC/AP/confusion matrix, best model, feature importance를 저장한다.

## 대안과 제외한 선택지

- 기존 `train-toc-detector`를 확장해 dataset row도 받는 방식은 제외했다. manual review label 기반 detector와 pseudo label dataset classifier는 입력 형식, feature 추출 책임, 평가 해석이 달라 한 명령에 섞으면 의미가 흐려진다.
- row 단위 무작위 split은 제외했다. 같은 PDF의 positive/negative sample이 양쪽 split에 섞이면 PDF 고유 layout을 외운 결과가 test 성능에 반영될 수 있다.
- 임시 분석 스크립트를 `outputs/`에 남기는 방식은 제외했다. 사용자가 production code 여부를 확인했기 때문에 CLI와 테스트가 있는 `src/` 구현으로 승격했다.

## 남은 리스크

- `bookmark_guided_toc_detection` label은 독립 수동 검수 ground truth가 아니므로, 현재 지표는 bookmark 기반 탐지 결과 재현 성능이다.
- `hist-gradient`는 sklearn의 native feature importance를 제공하지 않아 best model이 이 모델일 때 feature importance가 비어 있다.
- 생성 dataset의 negative sampling 정책이 positive와 1:1에 가깝게 맞춰져 있어 실제 모든 PDF page 분포에서의 precision/recall과 차이가 날 수 있다.
