- 전체 커밋 ID: `557bb87393453432d0c74216ec46393aea8207f3`

- 노트 생성 일시: `2026-07-19 16:28:10 +09:00`

## 변경 배경

- TestPyPI에 게시한 `0.1.0rc1` wheel과 sdist의 SHA-256이 registry metadata와
  일치했고, 별도 Python 3.12 환경에서 설치·CLI·Python version 검증이 통과했다.
- 검증된 RC를 정식 PyPI release로 승격하려면 source metadata와 lock의 package
  version을 prerelease가 아닌 `0.1.0`으로 고정해야 했다.
- release-readiness 테스트가 RC version을 하드코딩하고 있어 final metadata와
  불일치했으므로 테스트 계약도 함께 전환했다.

## 결정 내용

- `pyproject.toml`의 project version과 `uv.lock`의 local package version을
  `0.1.0`으로 일치시켰다.
- release metadata 테스트는 final version `0.1.0`을 명시적으로 검증한다.
- dependency 범위, public API, CLI와 artifact schema는 RC에서 검증한 상태를
  그대로 유지하고 version 외 동작 변경은 포함하지 않았다.

## 작동 방식

- `uv build`는 `pyproject.toml`의 `0.1.0`을 wheel과 sdist metadata에 기록한다.
- 설치된 package의 `__version__`과 CLI `--version`은 distribution metadata를
  읽으므로 final artifact 설치 시 `0.1.0`을 반환한다.
- release validator는 `v0.1.0`, source version과 wheel version이 같은지 검사하고,
  실제 tag 단계에서는 tag commit과 `origin/master` HEAD 일치도 추가로 검사한다.

## 대안과 제외한 선택지

- `0.1.0rc1` artifact를 정식 release로 재사용할 수는 없다. PyPI version과
  filename이 prerelease로 고정되며 게시된 artifact는 교체할 수 없기 때문이다.
- 테스트에서 prerelease와 final을 모두 허용하는 느슨한 assertion은 release
  metadata 오설정을 놓칠 수 있어 사용하지 않았다.

## 남은 리스크

- PyPI 게시 후 같은 `0.1.0` artifact를 수정하거나 재업로드할 수 없다. 따라서
  curated master CI와 registry hash를 게시 전후에 각각 확인해야 한다.
- build backend는 PEP 639 license metadata와 함께 기존 license classifier가
  deprecated됐다는 경고를 출력한다. 현재 metadata validation은 통과하지만 후속
  release에서 중복 classifier 제거를 검토할 수 있다.
