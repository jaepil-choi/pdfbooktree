## 변경 배경

- `experiments/experiments.json`과 PRD에서 확인한 흐름은 PDF text layer 추출, 기존 bookmark skip, TOC page 탐지, TOC item parsing, offset 추정, heading alignment, bookmark/Markdown export로 이어진다.
- 실험 001-003은 TOC page 탐지에 필요한 objective feature와 deterministic ensemble 가능성을 확인했다. 이 구현은 실험 코드를 바로 제품 코드로 옮기기 전에 public API, 데이터 모델, 단계별 모듈 경계를 먼저 고정하기 위한 scaffold다.
- v0.1 전체 알고리즘을 한 번에 구현하면 실험 코드의 임계값과 임시 구조가 패키지 API로 굳을 위험이 있어, 이번 커밋은 다음 구현자가 각 단계를 채울 수 있는 동작 골격까지만 만든다.

## 결정 내용

- `Processor`, `BatchProcessor`, `ProcessingConfig`, `ProcessingResult`를 공개 API로 노출했다. CLI entrypoint는 `pdfbooktree.cli:main`으로 옮겨 `__init__.py`가 API 노출만 담당하게 했다.
- 단계 간 데이터는 `models.py`의 dataclass로 정의했다. `PdfPageText`, `PageFeature`, `TocDetectionResult`, `TocItem`, `OffsetEstimate`, `AlignedTocItem`, `ContentRange`, `BookmarkPlanItem`을 통해 중간 산출물의 형태를 먼저 고정했다.
- 내부 page number는 모두 1-based로 통일하고, PyMuPDF에 접근할 때만 `utils/page_numbers.py`에서 0-based index로 변환하도록 했다.
- `pdf/`, `toc/`, `alignment/`, `output/`, `utils/`로 책임을 나눴다. `evaluation/`, `training/`, `llm/`, `pdf/document.py`, `toc/segments.py`는 아직 실제 책임이 충분하지 않아 만들지 않았다.
- TOC 탐지는 완성된 ensemble 이식이 아니라 `feature_heuristic_scaffold` entrypoint만 제공한다. offset 추정, PDF bookmark 삽입, Markdown 본문 export는 다음 구현 단계의 책임으로 남겼다.

## 작동 방식

- `Processor.run()`은 출력 디렉터리를 만들고, 기존 bookmark를 추출한 뒤 `skip_existing_bookmarks`가 켜져 있고 bookmark가 충분히 깔끔하면 `status="skipped"` 결과와 report를 반환한다.
- skip 대상이 아니면 앞부분 page text를 추출하고, page feature를 계산하고, scaffold TOC detector와 TOC line parser를 실행한다. 이후 단계는 아직 지원하지 않으므로 `status="failed"`와 명시적인 warning을 반환한다.
- `BatchProcessor.run()`은 입력 디렉터리의 PDF를 순회하고 각 PDF마다 `Processor`를 실행해 processed/skipped/failed count와 생성 산출물 경로를 집계한다.
- `output/intermediates.py`는 `toc_page_candidates.json`, `toc_raw.json` 등 PRD에서 요구한 중간 산출물 이름을 고정한다. `report.py`는 `ProcessingResult`를 JSON report로 저장한다.
- `toc/features.py`와 `toc/parse.py`, `alignment/ranges.py`, `utils/*`의 작은 순수 함수들은 scaffold 단계에서도 실제 동작하도록 구현했다.

## 대안과 제외한 선택지

- 실험 003의 deterministic ensemble을 곧바로 `toc.detect`에 완전히 이식하는 방법은 제외했다. API와 산출물 경계가 안정되기 전에는 임계값과 silver-label 전용 함수가 제품 코드에 섞일 가능성이 높기 때문이다.
- `evaluation/`, `training/`, `llm/` 디렉터리를 미리 만드는 방법도 제외했다. PRD상 필요한 확장점이지만 v0.1 scaffold에서 빈 파일만 늘어나면 역할 추적성이 떨어진다.
- `Processor.run()`에서 미구현 단계를 예외로 중단시키는 방법 대신 실패 결과와 warning을 반환하게 했다. CLI와 batch에서 현재 지원 범위를 사용자에게 보고할 수 있게 하기 위해서다.

## 남은 리스크

- `detect_toc_pages()`는 아직 얇은 heuristic scaffold라 실험 003 수준의 성능을 기대하면 안 된다. 다음 구현에서 bookmark anchor, printed page sequence, TOC entry pattern, window contrast, offset consistency labeler를 제품 코드로 이식해야 한다.
- `estimate_page_offset()`, PDF bookmark write, Markdown 본문 export는 아직 실제 산출물을 만들지 않는다.
- `Processor.run()`은 현재 skip이 아닌 PDF에 대해 의도적으로 `failed`를 반환한다. v0.1 동작 구현이 들어오면 processed 결과와 bookmark count, output path 생성 흐름을 완성해야 한다.
- full repository format check는 실험 파일 포맷 상태에 영향을 받는다. 실험 파일을 포맷할지 여부는 별도 실험 커밋 정책에 맞춰 결정해야 한다.
