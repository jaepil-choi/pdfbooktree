## 작동 방식

- `BatchProcessor.run()`이 PDF마다 `_run_one()` 실행 후 `BatchLogEvent`를
  `self.log.emit()`으로 내보내고, 전체 루프를 `try/finally`로 감싸 마지막에
  `self.log.close()`를 호출한다(`ScanBookmarkClassifier.run()`과 동일 패턴).
- CLI는 개별 PDF 실패를 command 실패로 보지 않는다 - `failed_count > 0`이어도
  exit 0이며, command 자체가 예외를 던질 때만 exit 1(runtime)/2(input/config)다.
- JSON final result는 stdout 한 줄, event는 stderr JSONL로 분리된다.

## 대안과 제외한 선택지

- CLI에서 `try/finally`로 logger를 닫는 방식도 고려했으나, `batch_logger`
  생성이 try 블록 밖에서 실패하면 `finally`에서 UnboundLocalError가 날 수
  있어 기각했다. 대신 `BatchProcessor.run()` 내부에서 닫는 기존
  `ScanBookmarkClassifier` 패턴을 따랐다.
- `process`처럼 모든 typography 옵션을 legacy flag로 노출하는 대신
  `infer`/`apply`와 같이 `--config`/`--set`만 노출했다 - legacy flag는
  `process`의 하위호환 부채이지 새 command가 따라야 할 패턴이 아니다.
