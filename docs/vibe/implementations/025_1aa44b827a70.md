## 변경 배경

- LLM fallback을 실행할 수 있는 환경을 선택 설치가 아니라 기본 설치 계약으로 바꾸기 위해
  기존 `llm` extra 의존성을 mandatory dependency로 올렸다.
- 동시에 `use_llm`의 의미가 "패키지 설치 여부"가 아니라 "실제 런타임 호출 여부"임을
  명확히 해야 했다. API key가 없는 일반 실행에서는 `use_llm=False` 경로가 계속 LLM
  클라이언트를 만들지 않아야 한다.
- `BookmarkTocBatchDetector`에는 병렬 worker를 위해 만든 top-level 처리 함수와 과거
  클래스 내부 helper가 중복으로 남아 있었다. 실제 `run()`은 top-level 함수만 사용하고
  있어서 유지보수 혼선을 줄일 수 있었다.

## 결정 내용

- `langchain-core`, `langchain-openai`, `langgraph`, `openai`, `pillow`,
  `python-dotenv`를 기본 dependency로 이동하고, `pdfbooktree[llm]`은 호환용 빈 extra로
  남겼다.
- `OpenAI` import는 mandatory dependency가 되었어도 client 생성 시점 lazy import로
  유지했다. 기본 import와 `use_llm=False` 실행이 API key나 네트워크 호출에 묶이지 않게
  하기 위한 결정이다.
- `BookmarkTocBatchDetector` 클래스는 PDF 검색, worker 실행, diagnostics, 결과 집계만
  담당하게 하고, PDF 단위 처리와 dataset row 생성은 top-level 함수 경로 하나로 통일했다.
- staged LLM TOC extractor는 prompt line marker를 `[Tn]`에서
  `<Tn x1="...">...</Tn>` 형태로 바꿔, 글씨 크기 tier와 줄 시작 x 좌표를 함께 전달한다.
  모델이 level을 새로 추론하지 않고 tag 숫자를 복사한다는 기존 정책은 유지했다.

## 작동 방식

- 패키지를 설치하면 LLM 관련 라이브러리가 기본으로 설치된다. 다만 `ProcessingConfig.use_llm`
  기본값은 `False`이므로, 명시적으로 켜기 전에는 range review와 item extraction fallback을
  호출하지 않는다.
- `--use-llm` CLI 옵션은 런타임에서 LLM fallback을 실제 호출할지 여부만 제어한다.
  `use_llm=True`에서 API key가 없으면 기존처럼 LLM client 생성 시 명확한 예외가 난다.
- bookmark TOC batch는 worker 수가 1이어도 2 이상이어도 `_process_pdf_for_bookmark_toc`
  경로를 사용한다. 이 함수가 bookmark 추출, 짧은 PDF/무문자 bookmark skip, TOC detection,
  dataset row 생성을 모두 수행한다.
- `TocVisualLine`은 줄 시작 x 좌표인 `x1`을 추가로 가진다. `annotate_page()`는 제목에
  `<`, `>` 같은 문자가 있어도 prompt tag 구조가 깨지지 않도록 HTML escape를 적용한다.

## 대안과 제외한 선택지

- `openai`만 mandatory dependency로 올리는 대안이 있었지만, 요구사항에 따라 기존 `llm`
  extra 전체를 기본 dependency로 이동했다.
- `use_llm` 기본값을 `True`로 바꾸는 선택지는 제외했다. dependency 설치 정책과 실제 LLM
  호출 정책은 분리되어야 하며, API key가 없는 환경의 기본 실행을 깨뜨릴 수 있기 때문이다.
- 클래스 내부 batch helper를 남겨두는 선택지는 제외했다. 사용되지 않는 중복 구현이 top-level
  worker 경로와 어긋날 위험이 더 컸다.

## 남은 리스크

- `pdfbooktree[llm]`은 빈 extra가 되었으므로 기능 차이는 없지만, 과거 설치 문서가 있다면
  기본 설치로 안내를 바꿔야 한다.
- 기본 dependency가 무거워졌기 때문에 새 환경 설치 시간과 lock 갱신 빈도는 늘 수 있다.
- `experiments/` lint 문제는 이번 구현과 별개로 남아 있다.
