## 변경 배경

- 직전 커밋(`361917b`)에서 AI agent가 진단 결과를 보고 parameter로 재분할하는 루프를 제품 계약으로 삼았다. 그 계약의 전제는 공개된 config key가 실제로 동작한다는 것이다.
- 그런데 경계 검토에서 `typography.min_tier_gap`이 소비자가 하나도 없는 공개 key라는 사실이 드러났다. 유일한 소비자였을 `_merge_close_tiers`는 호출자가 없어 같은 커밋에서 제거됐고, 실제 tier 병합은 `min_tier_count` 기반 `_merge_sparse_tiers`가 담당한다.
- `config explain`과 `config schema`에는 설명까지 붙어 노출되는데 pipeline 어디서도 읽지 않는다. agent가 `--set typography.min_tier_gap=...`을 줘도 오류도 경고도 없이 아무 일이 일어나지 않았다. 진단이 "이 override를 시도하라"고 안내하는 제품에서 무반응 knob은 agent에게 잘못된 인과를 학습시킨다.
- `TierSet.gap_merged_tier_count`도 같은 뿌리다. gap merge 단계가 사라진 뒤 `tiers.py`에서는 항상 `raw_tier_count`와, `geometry.py`에서는 항상 `len(tiers)`와 같은 값이었다. 세 counter 중 하나가 영구히 중복이면 읽는 쪽이 의미를 오해한다.

## 결정 내용

- 되살리지 않고 제거했다. gap 기반 병합은 실험 069/080에서 희소 tier 병합으로 대체됐고, 되살리면 검증되지 않은 동작을 다시 들이는 셈이다. 사용되지 않는다는 사실 자체가 제거의 근거다.
- `min_tier_gap`은 dataclass 정의와 범위 검증에서 함께 뺐다. config 계층이 unknown key를 이미 `invalid_config`로 거절하므로, 제거만으로 "조용한 무시"가 "명확한 거절"로 바뀐다.
- `gap_merged_tier_count`는 공개 `TierSet`과 두 tier artifact에서 동시에 제거했다. 남은 `raw_tier_count`와 `final_tier_count`는 각각 희소 병합 전후를 뜻해 서로 다른 정보를 준다.
- 공개 표면 변경이므로 CHANGELOG 한국어·영어 양쪽 Unreleased에 제거 항목으로 기록했다.

## 작동 방식

- `--set typography.min_tier_gap=3.0`은 이제 `invalid_config`로 실패하며 오류 메시지가 `typography.min_tier_count`, `typography.max_heading_tier`, `typography.heading_merge_gap_ratio`를 후보로 제시한다. agent는 무반응 대신 즉시 다음 후보를 알 수 있다.
- `config schema`와 `config explain typography.min_tier_gap`은 각각 key 부재와 unknown key 오류를 낸다.
- 새 run의 `font_size_tiers.json`과 `height_tiers.json`은 `signal`, `cut_points`, `tiers`, `raw_tier_count`, `final_tier_count`만 담는다.
- `TierSet` 생성자 인자가 6개에서 5개로 줄었다. 위치 인자로 만들던 호출부도 함께 고쳤다.

## 대안과 제외한 선택지

- `min_tier_gap`을 다시 소비하도록 gap 병합을 복원하는 안은 배제했다. 현재 tier 구성은 실험으로 검증된 희소 병합이고, 검증되지 않은 병합 단계를 되살리면 heading 후보 선택이 조용히 달라진다.
- key만 남기고 문서에 "미사용"이라고 적는 안도 배제했다. 문서가 아니라 동작이 계약이며, 미사용 key는 여전히 agent의 재시도 예산을 낭비시킨다.
- `gap_merged_tier_count`를 유지한 채 의미를 부여하는 안은 배제했다. 부여할 의미가 되살아난 gap 병합뿐이라 위와 같은 이유로 막힌다.
- 하위 호환을 위해 필드를 남기고 deprecation을 알리는 안도 배제했다. 저장소 방침이 호환 계층을 두지 않는 것이고, 아직 이 필드를 소비하는 코드가 저장소 안에 없다.

## 남은 리스크

- 공개 API와 artifact schema를 함께 바꾸는 breaking change다. 외부에서 `TierSet.gap_merged_tier_count`나 두 artifact의 해당 항목을 읽던 소비자는 이번 릴리스에서 깨진다.
- 이전 run이 만든 artifact에는 제거한 항목이 그대로 남아 있다. 새 코드가 그 값을 읽지는 않지만, 옛 artifact와 새 artifact를 같은 스키마로 가정해 비교하는 외부 도구는 차이를 볼 수 있다.
- `tests/test_bpe_markdown_split.py`가 넘기던 `min_tier_gap` 인자를 지우면서 그 테스트의 tier 구성 조건은 `min_tier_count`만 남았다. 의도한 검증 대상은 그대로지만 조건이 하나 줄었다.
