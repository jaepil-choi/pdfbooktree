## 변경 배경

- v0.1.0 공개 전에 Python 결과 객체를 API 응답, message queue와 저장소로 전달할
  공식 직렬화 경로가 필요했다. 내부 `utils.jsonio.to_jsonable()`은 CLI와 artifact

- package root가 고수준 workflow부터 lifecycle model까지 많은 symbol을 다시

- package skill에 Python API reference가 이미 포함됐지만 README와 PyPI metadata가

## 결정 내용

- `serialization.py`를 public module로 추가하고 package root에서 `JsonValue`,
  `to_jsonable()`, `to_json()`을 export했다. 기존 내부 import는
  `utils.jsonio` re-export를 유지해 한 번에 교체하지 않았다.
- 모든 결과 model에 동일한 method를 추가하지 않고, dataclass와 중첩 값을
  처리하는 함수형 직렬화 계약 하나를 제공했다.
- dataclass는 object, `PurePath`는 문자열, tuple/list는 array, `Enum`은 value로
  변환한다. 지원하지 않는 타입은 `TypeError`, NaN과 Infinity는 `ValueError`로
  거부해 조용한 문자열 fallback을 두지 않았다.
- root와 `pdfbooktree.ocr`, `pdfbooktree.classify`,
  `pdfbooktree.typography`의 `__all__`을 의도적으로 지원하는 public surface로
  문서화했다. 기존 root export는 축소하지 않았다.
- Python API reference를 skill의 canonical 상세 문서로 유지하고 README와
  `pyproject.toml`의 Documentation URL이 `master`의 해당 문서를 가리키게 했다.
  repo-local skill과 wheel bundle은 byte-identical하게 갱신했다.
- v0.1.0 OCR은 `engine="upstage"`만 지원하고 custom provider 등록·주입 API는
  없다고 README, SKILL.md와 Python API reference에 명시했다.
- help 테스트는 raw ANSI 문자열 대신 `rich.text.Text.from_ansi(...).plain`에서
  option을 검사하게 했다.

## 작동 방식

- `to_jsonable()`은 dataclass를 `asdict()`로 전개한 뒤 중첩 값을 재귀 변환한다.
  dict key는 문자열화하고 JSON scalar와 finite float만 그대로 반환한다.
- `to_json()`은 변환 결과를 `json.dumps()`에 전달하며 Unicode 보존 여부와
  indent를 호출자가 선택한다. `allow_nan=False`를 함께 적용한다.
- 기존 artifact writer는 public 변환 구현을 재사용하므로 CLI, report, manifest와
  library user의 변환 규칙이 분기되지 않는다.
- `pdfbooktree skill install`이 설치하는
  `references/python-api.md`에는 공개 import 기준, 주요 workflow, OCR 경계,
  결과 직렬화 규칙과 오류 조건이 포함된다.
- clean-wheel smoke는 설치된 wheel에서 한국어 title과 `Path`를 실제
  직렬화하고, 설치된 skill reference에 `__all__`, 직렬화와 Upstage-only 계약이
  존재하는지 검사한다. subprocess는 `PYTHONUTF8=1`로 고정해 Windows locale에
  따라 Unicode 검증이 달라지지 않게 했다.
- release source는 항상 `master`라는 정책을 릴리스 TODO에 기록했고,
  `develop`의 green commit을 `master`에 반영한 뒤 tag를 만드는 작업은 미완료
  gate로 남겼다.

## 대안과 제외한 선택지

- 모든 결과 dataclass에 `to_dict()`와 `to_json()` method를 반복 추가하는 방식은
  model마다 구현과 동작이 달라질 수 있고 외부 model 조합이 어려워 제외했다.
- root export를 고수준 API만 남기도록 축소하는 방식은 이미 사용 가능한 public
  import를 불필요하게 깨므로 제외하고 `__all__`을 명시적 facade 계약으로 삼았다.
- 사용자 문서와 skill reference에 별도 API 문서를 복제하는 방식은 세 사본의
  drift 위험을 키우므로 제외했다. skill reference를 canonical 문서로 유지하고
  README와 PyPI metadata에서 직접 연결했다.
- custom OCR provider registry를 public API로 만드는 방식은 v0.1.0의
  Upstage-only 범위를 넓히므로 제외했다.
- CI help에서 color를 강제로 끄는 방식은 CI/Rich 조합에 따라 ANSI가 남을 수 있어
  제외하고 실제 표시 text로 normalize한 뒤 검사했다.

## 남은 리스크

- 원격 Windows/Linux CI가 실제로 green인지 push 후 확인해야 한다.
- production release는 이 `develop` commit을 검증한 뒤 `master`에 반영하고
  `master`에서 `v0.1.0` tag를 만들어야 한다.
- PyPI Trusted Publishing workflow와 GitHub `pypi` environment는 별도 릴리스
  준비 작업으로 남아 있다.
- `to_jsonable()`은 Python model을 JSON 값으로 변환하는 규칙을 보장하지만,
  모든 result model의 field 호환성을 하나의 독립 schema version으로 묶지는
  않는다. versioned manifest와 CLI envelope는 각자의 기존 schema version을
  계속 사용한다.
- v0.1.0에는 Upstage 외 OCR provider와 custom provider 등록 API가 없다.
