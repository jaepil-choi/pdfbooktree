  `offset = pdf_page - book_page`의 최빈값을 잡으면 sample 5권 모두 정답 offset이 복원됨을 확인했다.

## 결정 내용

- band page number 추출은 geometry 계층 `pdf/page_numbers.py`로 분리했다. fitz `page.rect`/
  `page.get_text("words")`로 band word를 모아 같은 줄로 묶고, x 거리가 가까운 textbox를 병합해
  OCR이 쪼갠 숫자(`1`+`9`→`19`)를 복원한 뒤 `\d+` 그룹을 모두 후보로 뽑는다(글자 섞여도 거르지 않음).
- offset 통계/선택은 `alignment/offset.py`에 둔다. band별(all/bottom/top) 최빈 offset과 연속 run을
  구하고, best band = (run, modal_count) 최대값으로 고른다(experiment 015 선택 로직 그대로).
- clean 게이트는 **최빈 우세** 기준으로 정했다: `modal_count ≥ min_modal_count` 그리고
  `dominance_ratio(최빈/2위) ≥ min_dominance_ratio`. 미충족·미검출 시 `OffsetEstimationError`로
  fast-fail하며 fallback(LLM, 기본 offset 등)은 두지 않는다.
- 시그니처를 `estimate_page_offset(items, pages)` → `estimate_page_offset(pdf_path, config)`로 바꿨다.
  offset은 word box 좌표가 필수이고 TOC item과 무관해서 `items`/`PdfPageText`가 불필요하다.
  기존 호출자는 없고 `match.py`는 결과 타입 `OffsetEstimate`만 받으므로 영향이 없다.
- 파라미터·임계값을 전부 `config.OffsetEstimationConfig`로 노출했다(band_ratio, line_y_tolerance_ratio,
  merge_gap_ratio, max_number, max_scan_pages, min_modal_count=5, min_dominance_ratio=1.5).
- `models.BandPageNumber`를 추가하고 `estimate_page_offset`/`OffsetEstimate`/`OffsetEstimationError`/
  `OffsetEstimationConfig`를 패키지 public API로 export했다.

## 작동 방식

- `extract_band_page_numbers(pdf_path, config)`가 page마다 band 후보 `BandPageNumber`(pdf_page, number,
  text, band, x_ratio, y_ratio)를 만든다. 모든 page 번호는 1-based다.
- `estimate_page_offset`는 후보가 없으면 즉시 fast-fail한다. 있으면 band별로 `offset = pdf_page - number`를
  모아 `summarize_offsets`(최빈/2위/우세도)와 `longest_consecutive_run`을 계산한다.
- best band의 최빈 offset이 clean 게이트를 통과하면 `OffsetEstimate(offset, confidence=modal_share,
  evidence=[...])`를 반환한다. evidence head에 best_band, modal_count, dominance_ratio, run, coverage,
  top_offsets, `printed_page_1_estimated_pdf_page`를 PRD §9 형태로 담고, 일치 page 샘플을 덧붙인다.
- 통과 못 하면 진단 메시지(band/offset/modal_count/dominance/run/candidate 수)와 함께 예외를 던진다.

## 대안과 제외한 선택지

- clean 기준을 연속 run 길이로 두는 안(엄격)은 제외했다. 고려대2처럼 OCR 누락이 잦아 run이 짧아도
  최빈 offset이 압도적(76 vs 7)인 정답 케이스를 버리게 되어, 사용자가 최빈 우세(관대) 기준을 택했다.
- 글자 섞인 run을 거르는 필터는 제외했다. running header(`Part1...23`)에서도 `\d+` 그룹으로 page number가
  나오고, 연속 증가하는 진짜 page number만 통계에서 이기므로 거르지 않는 편이 단순하고 robust하다.
- `PdfPageText`에 좌표를 얹어 기존 시그니처를 유지하는 안은 제외했다. offset 전용 geometry를 text 모델에
  섞으면 책임이 흐려져, 별도 추출 계층으로 분리했다.

## 남은 리스크

- runtime `Processor`는 아직 `estimate_page_offset`를 호출하지 않는다. 파이프라인 연결(parsing→offset→
  alignment→write)은 후속 작업이다.
- 장별로 page 번호가 리셋되는 multi-segment numbering 책은 단일 global offset이 맞지 않을 수 있다.
  현재 sample 5권에는 없었으나(고려대2도 단일 -1), 향후 구간 분할이 필요할 수 있다.
- clean 게이트 기본값(min_modal_count=5, min_dominance_ratio=1.5)은 sample 5권 기준이다. 더 다양한
  레이아웃에서 false fast-fail/false accept가 나오면 config로 조정해야 한다.
- band scan은 기본 전체 page를 훑는다. 매우 큰 책에서 비용이 크면 `max_scan_pages`로 제한할 수 있다.
