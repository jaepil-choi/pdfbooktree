## 변경 배경

- PRD는 AI agent가 전체 processing 전에 PDF page count, 지정 page text, 기존 bookmark, OCR 품질과 진행 상태, bookmark plan을 terminal에서 빠르게 확인할 수 있어야 한다고 요구한다.
- 기존 CLI는 `process`, OCR 실행, 분류 중심이어서, 이미 생성된 artifact를 읽기만 하며 다음 행동을 결정할 inspection 명령이 없었다.
- 실험 083은 실제 수리통계학 partial OCR artifact에서 raw cache 수만으로는 page 누락을 판단할 수 없고, `ocr_progress.json`과 insertable JSON 내부의 1-based `pdf_page` 연속성을 함께 검사해야 함을 확인했다.

## 결정 내용

- 읽기 전용 public API를 `pdfbooktree.inspection`에 두고 package root에서도 `inspect_page_count`, `inspect_text`, `inspect_bookmarks`, `inspect_ocr_artifact`, `inspect_plan_artifact`를 import할 수 있게 했다.
- CLI는 새 `pdfbooktree inspect` 하위 명령에 `page-count`, `text`, `bookmarks`, `ocr`, `plan`을 추가했다. 각 명령은 기본 Rich 출력과 agent가 파싱할 수 있는 단일 JSON 출력(`--json`)을 함께 제공한다.
- OCR inspection은 output PDF 존재만으로 성공을 주장하지 않는다. target page, progress, raw/insertable cache, 중복 page, 완료 범위 누락, stats, 마지막 log event를 함께 읽어 `complete`/`partial`/`missing` 상태를 반환한다.
- page text CLI 입력은 기존 `parse_page_ranges`를 재사용하고, 외부 page 번호는 언제나 1-based로 검증한다.

## 작동 방식

- `inspect page-count <pdf>`는 PyMuPDF로 전체 page 수를 읽고, `inspect text <pdf> --pages 1-3`은 각 1-based page의 text와 char count를 반환한다.
- `inspect bookmarks <pdf>`는 기존 outline adapter를 재사용해 order, level, title, target page를 반환한다.
- `inspect ocr <artifact_dir>`는 OCR config에서 input PDF와 target page를 파악한다. progress의 완료 수에 대응하는 insertable page가 없는 경우에는 warning을 내고, raw cache 수와 고유 insertable page 수의 차이 및 중복 page도 표시한다.
- `inspect plan <output_dir>`는 `bookmark_plan.json` 또는 기존 outline plan, validation, processing report의 Markdown export 정보를 찾아 요약한다. artifact가 없더라도 stack trace 대신 `missing` 상태와 warning을 반환한다.

## 대안과 제외한 선택지

- inspection마다 별도 CLI 구현에서 PDF/artifact 읽기 로직을 중복하는 방식은 제외했다. Python public API와 CLI가 같은 결과 계약을 공유해야 agent와 library 사용자의 page convention 및 warning이 일치한다.
- raw cache 파일 수만 보여주는 방식은 제외했다. raw cache 파일명에는 page 번호가 없으므로, insertable JSON의 `pdf_page`와 progress를 함께 확인해야 어느 page가 실제로 준비됐는지 알 수 있다.
- partial artifact를 오류로만 종료하는 방식은 제외했다. 장시간 OCR은 중간 artifact를 보존하므로, agent가 `reuse` 실행으로 재개할 수 있도록 partial 상태와 첫 미처리 page를 반환하는 편이 유용하다.

## 남은 리스크

- v1 insertable cache 파일은 JSON 안에 cache schema version을 기록하지 않았으므로 inspection은 중복 page를 stale artifact 가능성으로 경고하지만, 각 파일이 어느 key version에서 왔는지는 판별하지 못한다.
- OCR output PDF와 stats는 OCR 모든 page가 끝난 뒤 생성된다. partial 실행 중에는 stats 부재가 정상일 수 있으며 inspection은 이를 상태와 함께 해석해야 한다.
- `inspect plan`은 현재 processor가 쓰는 대표 artifact와 report를 찾는다. 향후 artifact 파일명 계약이 확장되면 해당 탐색 규칙과 테스트를 함께 보완해야 한다.
