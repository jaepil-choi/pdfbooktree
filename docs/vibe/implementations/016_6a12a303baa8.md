- TOC page detection 다음 단계인 TOC item parsing(PRD 4.2/8)은 기존 regex
  `toc/parse.py`로 처리했는데, line-final number를 강제하고 영어/숫자 numbering
  패턴 전용이라 OCR 한국어 스캔본(`제1장`, 들여쓰기 제목, 깨진 leader)에서 거의
  실패했다.
- experiment 014에서 Upstage LLM으로 TOC page에서 항목을 구조화 추출하는 흐름을
  검증했다. 텍스트 경로(solar-pro2)가 john_hull f1 0.991, shreve 1.0,
  luenberger 0.912로 가장 안정적이었고, 이미지 경로(information-extract)는
  페이지별 호출이라 과추출 위험이 있었다. solar-pro3는 책마다 누락/과추출이
  심해 제외했다.
- 사용자가 solar-pro2로 확정하고 src 승격을 요청하면서, 모델·하이퍼파라미터·

## 결정 내용

- `pdfbooktree.toc.llm_extract.LlmTocExtractor`를 public interface로 추가했다.
  `extract(pdf_path, toc_pages)`가 `list[TocItem]`을 반환한다.
- 실험에 하드코딩돼 있던 값을 전부 `config.LlmTocExtractionConfig`로 옮겼다:
  `mode`, `text_model`, `image_model`, `chat_base_url`, `image_base_url`,
  `api_key_env`, `request_timeout`, `temperature`, `max_completion_tokens`,
  `default_item_confidence`, `max_image_pages`, `image_dpi`, `image_mime`,
  `system_prompt`. 기본 system prompt는 `config.py`에 상수로 두어 모듈 간
  순환 import를 피했다.
- 기본값은 experiment 014 결과에 따라 `mode="text"`, `text_model="solar-pro2"`,
  `temperature=0.0`으로 둔다.
- `TocItem.printed_page`와 `AlignedTocItem.printed_page`를 `int`에서
  `int | None`로 바꿨다. 목차에 페이지 번호가 없는 항목(예: 일부 머리말,
  깨진 마지막 항목)을 정직하게 표현하기 위해서다.
- `openai`는 optional dependency(`llm` extra)라 client 생성 import를 호출 시점에
  지연시켰다. 패키지 기본 import는 openai 없이도 동작한다.

## 작동 방식

- text 경로: `extract_selected_page_texts`로 TOC page 라인 텍스트를 뽑고
  `--- PDF page N ---` 마커와 함께 이어붙여 solar-pro2 chat에 보낸다.
  `response_format`은 `["integer","null"]` union을 허용하는 json_schema이고,
  `temperature`/`max_tokens`는 config에서 온다.
- image 경로: 각 TOC page를 `image_dpi`로 렌더해 base64로 만든 뒤
  information-extract 엔드포인트에 page별로 보낸다(이 API는 content에 이미지
  1개만 허용). 항목을 순서대로 병합한다. 이미지 스키마는 union 타입을 못 받아
  `printed_page`를 정수 단일 타입으로 둔다.
- `_to_item`은 LLM 출력을 `TocItem`으로 변환한다. `title`은 `normalize_text`로
  정리하고, `printed_page`가 0/None이면 `None`으로, `source_pdf_page`가 입력
  TOC page 집합에 없으면 가장 앞 TOC page로 보정한다. `confidence`는
  `default_item_confidence`. title이 빈 항목은 버린다. 모든 page 번호는 기존
  규칙대로 1-based다.
- 테스트/재현을 위해 `chat_client`/`image_client`를 주입할 수 있고, 주입하지
  않으면 config로 lazy 생성한다.

## 대안과 제외한 선택지

- solar-pro3/solar-pro4: pro4는 존재하지 않고, pro3는 같은 프롬프트·temperature
  0에서도 john_hull 46개 누락, luenberger 474개 과추출로 불안정해 제외했다.
  reasoning형 모델이 긴 고정 스키마 리스트를 끝까지 채우는 데 안 맞아 보인다.
- image 경로를 기본으로 두는 안: 제목 텍스트 품질은 더 좋지만 페이지별 호출
  과추출/중복과 장 레벨 printed_page 누락이 있어 기본은 text로 두고 image는
  옵션으로 남겼다.
- `printed_page`를 0 sentinel로 두는 안: 의미가 흐려져 `int | None`로 정확히
  표현하고 `alignment/match.py`만 가드했다.
- CLI 명령과 Processor 연동(regex parser 교체)은 이번 범위에서 제외했다.
  런타임 경로를 바꾸면 영향이 커서 별도 작업으로 둔다.

## 남은 리스크

- 기존 runtime `Processor`는 여전히 regex `toc/parse.py`를 쓴다. `LlmTocExtractor`는
  아직 파이프라인에 연결되지 않은 독립 public API다.
- text 경로는 OCR 텍스트에 띄어쓰기가 없으면 제목 공백이 붙어 나온다(한국어
  스캔본). 후처리나 image 경로 보완이 필요할 수 있다.
- per-item confidence가 LLM에서 오지 않고 `default_item_confidence` 고정값이라,
  PRD의 low-confidence LLM fallback 트리거로 바로 쓰기엔 부족하다.
- showcase 002 luenberger 사례 정정: 낮은 precision(0.25)은 과추출이 아니라
  weak reference 한계였다. bookmark 29개가 Part/Chapter만 담아 section/subsection이
  빠진 것이고, LLM은 목차 전 계층(L3/L4)을 정상 추출했다. 다만 (1) 간략/상세
  contents가 모두 한 page range에 있어 chapter가 중복되는 점, (2) OCR 제목 노이즈
  일부 잔존은 실제 남은 과제다.
- OCR 제목 노이즈 대응으로 system_prompt에 교정 지시를 넣어 다수가 복원되지만
  ('Char:.ter O'→'Chapter 10' 등) 'Chapter '1', 'fVIoney', 'Wi0il' 같은 일부는
  여전히 남는다. 간략/상세 contents 중복은 dedup 후처리가 필요하다.
- 라이브 호출 비용/재현성: 스키마·temperature 0으로 안정화했지만 모델 snapshot
  변경 시 결과가 달라질 수 있어, 재현이 필요하면 `solar-pro2-251215`처럼 고정
  snapshot을 config로 지정해야 한다.
