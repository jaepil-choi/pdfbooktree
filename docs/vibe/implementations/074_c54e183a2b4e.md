## 작동 방식

- CLI help는 Rich table을 거치지 않아 terminal width와 무관하게 option token을
  그대로 출력한다. command callback과 processing logger는 바꾸지 않았다.
- CI의 package job은 Ubuntu/Python 3.12에서 sdist와 wheel을 한 번 build하고
  `twine check` 뒤 `distributions` artifact로 올린다. 6개 wheel-smoke job은 같은
  artifact를 내려받아 선택한 Python minor의 두 clean venv(core, OCR extra)에
  설치한다. 마지막 `ci-green`은 선행 job 결과가 모두 success인지 확인한다.
- release workflow는 tag checkout에서 현재 `origin/master`를 fetch하고
  `validate_release.py`로 channel별 tag 형식, `pyproject.toml`, wheel METADATA와
  commit identity를 비교한다. checksum과 attestation 이후에만 보호 environment의
  OIDC publish 단계로 이동한다.
- TestPyPI는 별도 runner에서 정확한 RC version을 설치해 version/help를 확인한다.
  production은 core와 `[ocr]` 설치를 확인한 뒤 CHANGELOG에서 release notes를
  추출하고 GitHub Release에 wheel, sdist와 `SHA256SUMS`를 첨부한다.
- `bookmark_plan.json`, Markdown YAML/wiki relation, public 1-based page, JSON
  stdout와 progress stderr, exit code 의미는 변경하지 않았다.

## 대안과 제외한 선택지

- ANSI를 제거한 뒤 기존 Rich help를 테스트하는 방식은 renderer가 실제 사용자에게
  보여주는 option 축약을 고치지 못하므로 제외했다.
- 각 matrix job에서 wheel을 다시 build하는 방식은 게시 대상과 다른 artifact가
  통과할 수 있으므로 제외했다.
- PyPI API token과 장기 secret은 OIDC Trusted Publishing보다 회전·노출 위험이
  커서 제외했다.
- package version `0.1.0` 하드코딩은 RC와 후속 patch에서 smoke가 drift하므로
  wheel METADATA를 기준으로 바꿨다.
- Application Control 차단을 위해 `C:\tmp`에 launcher를 복사하거나 policy를
  우회하지 않았다. 저장소 output 아래 clean venv와 명시적 Python entrypoint만
  사용했다.
- analysis cache, batch resume/jobs, `doctor`, encrypted PDF password, 자동
  OCR policy와 실제 PDF showcase 재실행은 0.1.0 범위에서 제외했다.

## 남은 리스크

- workflow 파일은 local YAML parse와 contract test를 통과했지만 실제
  GitHub-hosted Windows/Linux × Python 3.12~3.14 run은 push 후 확인해야 한다.
  `ci-green` 실패 상태에서는 master 반영과 tag 생성을 금지해야 한다.
- PyPI/TestPyPI pending publisher, `testpypi`/`pypi` environment reviewer와
  `develop`/`master` branch protection은 repository 밖의 상태다. 별도 명시적
  승인으로 설정하기 전에는 publish workflow가 성공할 수 없다.
- RC 성공 전에는 source version을 `0.1.0`으로 바꾸거나 final tag를 만들 수 없다.
  문제가 있으면 기존 artifact를 교체하지 않고 `rc2`, `rc3`로 올려야 한다.
- 400권 평가는 2026-07-15의 embedded outline weak reference 기준이며 책별 품질
  편차가 크다. 문서의 수치를 자동 정확도 보증으로 해석하면 안 된다.
- corporate Application Control 정책에서는 새 unsigned venv launcher가
  차단될 수 있다. GitHub runner의 실제 console-script smoke와 게시 후 설치
  검증이 최종 배포 gate다.
