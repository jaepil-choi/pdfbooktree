  제품 코드로 옮긴 구현이었다. 이 방식은 한국어 OCR 목차처럼 글씨 크기가 장/절을
  나누는 책에서는 안정적이었지만, 영어 금융/수학 교재처럼 같은 글씨 크기 안에서
  들여쓰기와 글꼴이 계층을 나누는 책에서는 chapter/section 구조가 평탄화됐다.

  LLM level 자유 판단이 장/절을 역전했고, raw indent는 OCR jitter와 dot leader 때문에
  과분할됐다.
- experiment 029는 결정론 멀티피처 클러스터(height, indent column, bold, font_type)를

  보였다. Hull은 abs level agreement 0.9545, rel depth 0.9436까지 개선됐고,
  Shreve도 4단계 계층을 복구했다.
- experiment 030은 이 클러스터 계층 위에 `[Ln]` marker 기반 page extraction과 제목
  OCR 교정을 얹어 end-to-end로 검증했다. 사용자는 fallback/비교용 전략을 남기지 말고
  최신 검증 전략으로 production extractor를 교체하라고 결정했다.

## 결정 내용

- `toc/staged_llm_extract.py`의 내부 알고리즘을 height tier-cap 방식에서 clustered staged
  방식으로 교체했다. public class 이름 `SizeAwareStagedTocExtractor`는 기존 import 계약을
  깨지 않기 위해 유지하지만, 실제 동작은 experiment 029/030의 최신 전략을 따른다.
- 새 내부 모델 `ClusteredTocLine`을 추가해 `pdf_page`, `text`, `height`, `title_x`,
  `page_width`, `is_bold`, `font_type`, `trailing_page`를 함께 보관한다. 기존
  `TocVisualLine`은 호환용 테스트/helper 입력으로 계속 받을 수 있다.
- 계층 결정은 세 단계로 나눴다.
  1. 코드는 PyMuPDF span에서 height, indent column, bold, font family를 추출하고 signature
     cluster를 만든다.
  2. LLM은 클러스터 목록만 보고 cluster별 level을 반환한다. 같은 구조 단위는 같은 level로
     병합할 수 있다.
  3. 코드는 cluster level을 dense-rank해 각 줄의 확정 `[Ln]` marker를 만들고, page별
     extraction LLM은 그 level 숫자를 복사만 한다.
- 제목 OCR 교정은 별도 마지막 단계로 분리했다. 항목 수, 순서, level, printed page는 유지하고
  title 문자열만 교정한다.
- `ProcessingConfig.llm_item_extraction_strategy`를 제거했다. `use_llm=True`인 runtime에서는
  regex 파서 결과가 있더라도 최신 clustered staged extractor가 item extraction을 소유한다.
  기존 `basic` extractor는 standalone public API로는 남지만 production processor 경로에서는
  더 이상 선택되지 않는다.
- CLI `--use-llm` 설명도 fallback이 아니라 LLM range review와 clustered item extraction을
  실제 호출하는 옵션으로 정리했다.

## 작동 방식

- `Processor.run()`은 TOC range를 정한 뒤 `use_llm=True`이면 `SizeAwareStagedTocExtractor`를
  호출해 TOC item을 만든다. 이때 결정적 regex 파서가 item을 뽑았는지와 무관하게 최신 LLM
  경로가 우선한다.
- `extract_clustered_toc_lines()`는 1-based TOC page 목록을 받아 각 page의 text dict를 순회한다.
  한글 또는 라틴 2글자 이상이 있는 span만 content span으로 보고, line의 대표 height,
  첫 content span x 좌표, bold flag, font family, trailing number를 추출한다.
- `build_clusters()`는 height KDE cut, robust indent column, bold 여부, font family를 signature로
  삼아 content line을 클러스터링한다. indent column은 OCR jitter가 작을 때만 신뢰하고, 그렇지
  않으면 column 신호를 폐기한다.
- `_decide_cluster_levels()`는 클러스터 요약을 LLM에 보내 cluster별 level을 받는다. prompt는
  병합과 분리를 모두 허용하되 줄 단위 재분류는 금지한다.
- `annotate_page_levels()`는 각 TOC page 줄 앞에 확정된 `[Ln]` marker를 붙인다. `_extract_page()`는
  page별로 항목 분리와 printed_page 추출을 수행하며, LLM이 반환한 level은 marker 복사 결과로만
  받아들인다.
- `_correct_titles_by_page()`는 page별 item title 목록을 1:1 교정한다. 응답 개수가 맞지 않으면
  원문 title을 유지한다.

## 대안과 제외한 선택지

- 기존 height tier-cap extractor를 fallback이나 비교용으로 남기는 선택지는 제외했다. 사용자가
  최신 검증 전략을 production으로 채택해 교체하라고 명시했고, fallback은 실제 처리 품질을
  낮은 구버전 경로로 되돌릴 수 있다.
- LLM이 줄마다 level을 직접 결정하는 방식은 제외했다. experiment 027에서 한국어 계층 역전과
  영어 over-deepen이 반복됐다.
- raw `title_x` 들여쓰기만 primary depth signal로 쓰는 방식은 제외했다. experiment 024에서
  OCR jitter와 dot leader가 phantom column을 만들어 Hull 계층이 붕괴했다.
- regex parser가 item을 이미 뽑으면 LLM item extraction을 건너뛰는 이전 fallback 구조도 제외했다.
  최신 extractor의 목적은 단순 보완이 아니라 계층 품질을 책임지는 production item extraction이다.

## 남은 리스크

- Luenberger류 스캔 OCR 책은 장 헤더 cluster가 font/bold noise로 오염될 수 있다. live showcase에서도
  source grounding은 높지만 weakref 계층 일치가 낮았다. experiment 030에서 분리한 대로
  `Chapter`/`Part` prefix lexical promotion을 cluster 형성 전 단계에 추가하는 후속 작업이 필요하다.
- 2단 목차의 pane/gutter line reconstruction(experiment 037)은 아직 제품 extractor에 통합되지 않았다.
  이번 커밋은 029/030 계층 엔진 교체에 집중했고, Zvi Bodie 같은 2단 목차의 일부 reorder/중복 문제는
  후속으로 남는다.
- title correction은 LLM 품질에 의존한다. 한국어 OCR에서 source grounding 103/109처럼 개선됐지만,
  `기긴을 음켜쥐어라`, `미래여구-원` 같은 복원 실패는 남는다.
- `use_llm=True`일 때 item extraction LLM 호출 수가 늘어난다. live showcase 5권 실행은 시간이 오래
  걸렸고, batch 처리 비용/시간 관리는 별도 정책이 필요하다.
