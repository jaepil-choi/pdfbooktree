## 결정 내용

- 저장소용 skill과 배포용 템플릿을 각각 `.agents/skills/use-pdfbooktree`와 `src/pdfbooktree/_skill_templates/use-pdfbooktree`에 두고, 테스트로 두 복사본의 파일 목록과 내용을 동일하게 유지한다.
- Python 공개 인터페이스는 `install_project_skill(project_dir=".", force=False)`와 결과·예외 타입으로 제공하고, CLI는 `pdfbooktree skill install` 하위 명령으로 제공한다.
- 기본 동작은 기존 skill을 덮어쓰지 않는다. 사용자가 `--force` 또는 `force=True`를 명시한 경우에만 전체 디렉터리를 교체한다.
- 설치 중 일부 파일만 남는 상태를 피하려고 같은 부모 디렉터리에 staging 디렉터리를 만든 뒤 대상과 교체한다. 기존 대상은 임시 backup으로 이동하고, 실패하면 복구를 시도한다.
- 심볼릭 링크나 junction을 통한 프로젝트 밖 변경을 막기 위해 프로젝트 경계와 링크 계열 경로를 검사한다.
- 설치 skill에는 Python API와 CLI 전반뿐 아니라 `ocr-overlay-batch --min-page-count`의 기본값, 유효 범위, dry-run 예시와 제외 사유를 포함했다.

## 작동 방식

- 설치 함수는 `importlib.resources`로 패키지에 포함된 skill 트리를 순회해 staging 디렉터리에 복사하고, 대상이 없으면 바로 이름을 바꿔 설치한다.
- 대상이 이미 있으면 기본적으로 `SkillInstallError`를 발생시킨다. 강제 모드에서는 기존 대상을 backup으로 옮긴 뒤 staging을 대상 위치로 바꾸며, 성공하면 backup을 제거한다.
- 성공 결과는 프로젝트 경로, 설치 경로, 설치 파일 목록, 기존 대상 교체 여부를 `SkillInstallResult`로 반환한다.
- CLI는 현재 디렉터리를 기본 프로젝트로 사용하고 `--project-dir`, `--force`, `--format`, `--debug`를 지원한다. JSON 출력의 command는 `skill.install`이며 설치 오류는 종료 코드 2와 `skill_install_error`로 보고한다.

## 대안과 제외한 선택지

- 사용자 홈의 전역 skill 설치는 프로젝트별 버전과 사용법을 저장소에 고정할 수 없어 제외했다.
- 실행 시 네트워크에서 skill을 내려받는 방식은 오프라인 설치와 패키지 버전 재현성을 해쳐 제외했다.
- 기존 디렉터리에 파일을 하나씩 덮어쓰는 방식은 삭제된 템플릿 파일이나 부분 실패 흔적을 남길 수 있어 전체 디렉터리 교체 방식을 선택했다.

## 남은 리스크

- 저장소용 skill과 배포용 템플릿이 물리적으로 중복되므로 새 기능 문서를 추가할 때 두 위치를 함께 갱신해야 한다. 동기화 테스트가 누락을 감지한다.
- 강제 설치는 대상 skill에 사용자가 직접 추가한 파일도 모두 교체한다. 기본 보호와 명시적 `--force`가 이 위험을 사용자 선택으로 제한한다.
- 현재 설치 대상은 패키지가 제공하는 `use-pdfbooktree` 하나로 고정되어 있다. 여러 skill을 제공하게 되면 이름 선택과 목록 조회 인터페이스를 별도로 설계해야 한다.
