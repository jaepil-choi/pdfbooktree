## 변경 배경

OCR overlay overwrite(f9dbba1)를 `300STUDY`처럼 1000개 넘는 실제 서재 디렉터리에 적용하려면, "bookmark 없는 scanned PDF"만 골라내는 배치 분류가 먼저 필요하다. 실험 065~068(`experiments/065_*.py`~`068_*.py`)에서 embedded font 이름 같은 도구별 특징이 아니라 PDF 구조의 본질적 정의로 기준을 좁혔다: scanned page는 시각적 내용이 사실상 하나의 raster image이고, invisible OCR text overlay는 "문자 추출 가능"과 무관하게 실제 시각적 내용이 아니다.

## 결정 내용

- `is_scanned` 판정: 표본 page 전부가 scan-like(`scanned_page_fraction == 1.0`)이고 `total_visible_chars_sampled == 0`일 때만 True. 하나라도 어긋나면 `reject_reasons`에 실패한 조건과 실측값을 문자열로 남긴다.
- page 단위 scan-like 판정은 `image_coverage_ratio >= 0.85`(최대 단일 image가 page 면적을 얼마나 덮는지) AND `visible_char_count < 10`(PyMuPDF `get_texttrace()`의 render mode가 invisible(3)/clip-only(7)이 아닌 실제 paint된 문자 수)이다.
- bookmark 판정은 `has_meaningful_bookmark()`로 별도 분리했다. 기존 `is_clean_bookmark_set`(training gold-label 후보용, >=10개 요구)과 다른 목적이라 재사용하지 않고, level 구조(`toc_level_count >= 2`)만 요구하는 완화된 기준을 새로 만들었다.
- 최종 target: `is_scanned AND NOT has_meaningful_bookmark`.
- 배치 실행은 file 단위 `ClassifyLogEvent`/`ClassifyLogger` Protocol을 새로 만들어 `ocr/logger.py`와 동일한 Rich/Plain/JSON 패턴을 재사용했다.
- CSV(`classification_report.csv`)는 파일마다 즉시 flush, JSONL(`classification_detail.jsonl`)에는 page 단위 상세까지 포함, 종료 후 `classification_summary.json` 집계를 남긴다.
- `--dry-run`은 report 파일을 디스크에 쓰지 않고 콘솔 집계만 보여준다(1000개 배치 전 빠른 미리보기 용도).

## 작동 방식

`classify_scan(pdf_path)`이 `sample_page_indices`로 문서 전체에 걸쳐 최대 20page를 균등 sampling하고, 각 page를 `analyze_page`로 채점해 `ScanClassification`을 만든다. `ScanBookmarkClassifier.run()`은 디렉터리를 recursive/non-recursive로 순회하며 각 PDF에 대해 `classify_scan` + `extract_existing_bookmarks`를 호출하고, corrupt PDF 등 예외는 `_classify_one`에서 잡아 `error` 필드가 채워진 row로 남긴 채 배치를 계속한다. CLI는 `pdfbooktree classify-scan <dir> --output-dir <out> [--recursive] [--dry-run]`으로 노출된다.

## 대안과 제외한 선택지

- embedded font subset 접두어(`ABCDEF+`) 기반 판정: 6/6 샘플에서는 맞았지만 특정 조판/스캔 도구 이름 관행에 기댄 overfit 기준이라는 지적을 받아 제외했다.
- `is_clean_bookmark_set` 재사용: >=10개 bookmark 요구가 "짧지만 진짜인 목차"를 걸러낼 수 있어, 목적이 다른 `has_meaningful_bookmark`를 새로 분리했다.

## 남은 리스크

- 300STUDY 전체 배치는 아직 실행 전이라 실제 target 분포, 처리 시간, edge case는 검증되지 않았다.
- `IMAGE_COVERAGE_THRESHOLD=0.85`, `VISIBLE_CHAR_THRESHOLD=10`, `max_sample_pages=20`은 6개 labeled 샘플로만 검증한 값이라 대규모 배치에서 재조정이 필요할 수 있다.
- 분류 결과(`is_ocr_overwrite_target`)를 실제 OCR overlay 배치 실행으로 연결하는 단계는 아직 구현하지 않았다.
