- 전체 커밋 ID: `93c38bf00226f6b1366217ac4c040fd020d85349`
- 커밋 일시: `2026-07-08T11:00:53+09:00`
- 노트 생성 일시: `2026-07-08 11:01:03 +09:00`

## 변경 배경

- `금리의 경제학` 전체 OCR overlay 실행 중 77쪽 Document Parse 호출에서 `Server disconnected without sending a response.` 오류가 발생했다.
- 기존 `UpstageOcrEngine.recognize_page()`는 HTTP 응답을 받은 뒤 `raise_for_status()`에서 발생하는 오류와 429만 재시도했다.
- 실제 실패는 `httpx.Client.post()` 단계에서 응답 객체가 생성되기 전에 발생한 transport 오류라 기존 retry 범위에 들어오지 못했다.

## 결정 내용

- `max_retries` 기본값을 3으로 낮추고, retry 대기 시작값을 `retry_initial_wait_sec=2.0`으로 추가했다.
- 재시도 횟수는 실패 후 재시도 수로 해석한다. 따라서 기본값 3은 최초 호출 1번과 재시도 3번, 총 4번의 호출을 의미한다.
- 429 전용 분기와 HTTP status 오류 전용 분기를 합쳐, `client.post()`부터 `raise_for_status()`까지의 예외를 하나의 retry 경로로 처리한다.
- 기존 CLI의 `--engine-option key=value` 확장 지점을 그대로 사용해 `max_retries`와 `retry_initial_wait_sec`를 호출 시 조정할 수 있게 했다.

## 작동 방식

- `recognize_page()`는 `range(self.max_retries + 1)`로 호출을 시도한다.
- 각 실패 후 마지막 시도가 아니면 `_retry_wait_sec(attempt)`만큼 대기한다.
- 기본 대기 시간은 `2, 4, 8`초이며 `retry_initial_wait_sec * (2 ** attempt)`로 계산한다.
- 마지막 시도까지 실패하면 가장 마지막 예외를 그대로 다시 발생시켜 사용자에게 원인을 숨기지 않는다.

## 검증

- `uv run pytest tests\test_ocr_upstage_adapter.py`
- `uv run ruff check src\pdfbooktree\ocr\engines\upstage.py tests\test_ocr_upstage_adapter.py experiments\064_interest_economics_strip_text_overlay.py`
- 새 테스트는 `httpx.RemoteProtocolError`가 3번 발생한 뒤 4번째 호출에서 성공하는 fake client를 사용해 호출 횟수와 대기 시간 `[2.0, 4.0, 8.0]`을 확인한다.

## 대안과 제외한 선택지

- 429의 `Retry-After` 헤더를 별도로 우선 적용하는 방식을 유지할 수도 있었다. 이번 장애는 transport 오류였고 사용자가 명시한 정책이 `2, 4, 8`초였으므로 모든 재시도 가능 오류에 같은 지수 backoff를 적용했다.
- builder 레벨에서 page 전체를 재시도하는 방법도 가능하지만, 실패 지점은 OCR provider 호출 내부이므로 engine adapter가 책임지는 편이 cache와 logging 흐름을 덜 흔든다.

## 남은 리스크

- 모든 `httpx.HTTPStatusError`가 재시도 대상이 되므로, 인증 실패 같은 4xx도 기본 3회까지 반복될 수 있다.
- 장기적으로는 status code별 retry 가능 여부를 나누고, 429는 provider의 `Retry-After`를 존중하는 정책을 다시 도입할 수 있다.
