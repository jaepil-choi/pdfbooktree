## 변경 배경

- `ProcessingConfig.ocr_policy`와 JSON Schema는 `never`, `auto`, `always`를
  허용했지만 `Processor`는 `auto|always`에서 OCR을 실행하지 않고 처리 후 warning만
  남겼다. public config가 성공을 반환하면서 요청한 동작을 수행하지 않는 상태였다.
- 실험 `107_ocr_policy_supported_contract.py`에서 `auto|always`가 direct config,
  section data loader와 `--set` 세 경로에서 모두 허용되는 불일치를 재현했다.
- 자동 OCR 연결은 credential, API 비용, cache, 기존 bookmark overwrite 확인과
  원본 비파괴 output 정책을 함께 결정해야 하므로 release blocker를 닫는 작은
  수정으로 다루기에는 범위가 컸다.

## 결정 내용

- `ProcessingConfig.ocr_policy`의 타입을 `Literal["never"]`로 축소했다. config
  schema와 `config explain`도 같은 enum 하나만 노출한다.
- `auto`, `always`와 그 밖의 값은 별도 `ocr-overlay` 또는
  `ocr-overlay-batch` 실행을 안내하는 `ConfigError`로 조기 거부한다.
- 도달할 수 없게 된 `Processor.run()`의 늦은 OCR warning 분기를 제거했다.
- config schema version은 1을 유지했다. 아직 공개 릴리스 전이고 실제로 동작하지
  않던 값을 제거하는 contract correction이므로 새 version을 병행 지원할 실익이
  없다고 판단했다.
- repo-local `use-pdfbooktree` skill과 package bundle template을 같은 내용으로
  갱신해 설치 위치에 따라 OCR 안내가 달라지지 않게 했다.

## 작동 방식

- direct `ProcessingConfig` 생성은 `__post_init__()`에서 `never` 이외의 값을
  거부한다.
- TOML, CLI option과 `--set`은 모두 `resolve_processing_config()`가
  `ProcessingConfig`를 생성하는 경로를 지나므로 같은 `ConfigError`를 반환한다.
- CLI의 기존 input/config error handler가 오류를 `invalid_config` JSON envelope와
  exit 2로 변환한다. 따라서 PDF 분석, run/output directory 생성과 외부 OCR API
  호출 전에 종료된다.
- 기본값 `never`의 config data/hash와 기존 처리 결과는 유지된다. OCR이 필요하면
  별도 overlay 명령으로 새 PDF를 만든 뒤 그 PDF를 `infer` 또는 `process`에
  전달한다.

## 대안과 제외한 선택지

- `auto|always`를 곧바로 `OcrOverlayBuilder`에 연결하는 방식은 외부 비용과
  credential, cache policy, overwrite confirmation, 중간 OCR PDF lifecycle을
  암묵적으로 결정하게 되므로 제외했다.
- enum은 유지하고 warning을 더 강하게 표시하는 방식은 여전히 성공 결과와 실제
  동작이 불일치하므로 제외했다.
- `ocr_policy` field 자체를 제거하는 방식은 기존 기본 config shape와 hash를
  불필요하게 바꾸므로 제외하고 실행 가능한 `never` 값을 명시적으로 남겼다.

## 남은 리스크

- 기존 로컬 TOML에 `auto|always`가 있으면 이제 명시적으로 실패한다. 사용자는
  값을 `never`로 바꾸고 OCR overlay를 별도 단계로 실행해야 한다.
- 향후 자동 OCR을 다시 도입하려면 단순 enum 확장이 아니라 비용 예상, cache,
  overwrite 확인과 실패 복구를 포함한 end-to-end 계약이 필요하다.
- 전체 Ruff baseline, LICENSE/PyPI metadata와 wheel 설치 smoke test는 별도 release
  blocker로 남아 있다.
