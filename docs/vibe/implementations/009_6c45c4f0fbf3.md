## 변경 배경

- bookmark-guided TOC range가 전체 후보 구간을 잘 잡더라도 시작 page와 끝 page가 실제 bookmark 경계를 담지 않는 경우가 있었다.
- 사용자는 첫 bookmark page가 첫 번째 top-level bookmark를 반드시 담고, 마지막 bookmark page는 마지막 top-level bookmark를 기준으로 판단해야 한다고 정의했다.
- 007 경계 검수 실험과 showcase 재실행에서 simple contents page 뒤에 full contents page가 이어지는 tricky case가 확인되어, 시작 경계는 왼쪽부터, 끝 경계는 오른쪽부터 찾는 방식이 필요했다.

## 결정 내용

- public interface는 바꾸지 않고 `detect_toc_pages_from_bookmarks()` 내부 후처리만 확장했다.
- 경계 강제는 bookmark 전체가 아니라 top-level bookmark 그룹을 기준으로 수행한다.
- 시작 page는 첫 top-level bookmark 그룹의 match 중 왼쪽 page를 우선 선택한다.
- 끝 page는 마지막 top-level bookmark 그룹의 match를 오른쪽에서 찾고, 마지막 top-level match 다음 page에 child bookmark match가 있으면 `N+1`까지만 완화한다.
- 기존 feature vote와 segment selection 결과는 `anchor_pages`로 보존해 경계 선택의 기준으로 사용한다.

## 작동 방식

- 기존 detector가 후보 TOC page를 고르고 bookmark match를 포함하도록 확장한 뒤, `enforce_boundary_bookmark_matches()`가 최종 range를 다시 고정한다.
- `select_top_level_boundary_bookmarks()`는 입력 bookmark의 최소 level을 top-level로 보고 양끝 그룹을 고른다.
- 시작 경계는 첫 top-level 그룹의 parent와 child match 중 허용된 page 안에서 가장 앞쪽 match를 선택한다.
- 끝 경계는 마지막 top-level match가 있으면 오른쪽 match를 고르고, 바로 다음 1-based PDF page에 child match가 있을 때만 end page를 하나 늘린다.
- 마지막 top-level match가 없으면 해당 top-level 그룹의 child match 중 가장 오른쪽 page를 end page로 사용한다.
- 첫 경계 또는 마지막 경계 match를 찾지 못하면 bookmark-guided range를 확정할 수 없으므로 빈 결과로 처리한다.

## 대안과 제외한 선택지

- 모든 bookmark를 동일하게 경계 조건으로 쓰는 방식은 child bookmark가 많은 책에서 시작/끝 경계를 과하게 흔들 수 있어 제외했다.
- 마지막 page를 child match가 나오는 모든 뒤쪽 page까지 확장하는 방식은 body heading 반복을 TOC로 오인할 수 있어 제외했다.
- 별도 public option을 추가하는 방식은 현재 요구가 bookmark-guided detector의 기본 정확도 개선이므로 보류했다.

## 남은 리스크

- top-level bookmark title이 목차 본문에 축약되거나 번역되어 나타나는 PDF에서는 여전히 match 자체가 부족할 수 있다.
- simple contents와 full contents가 여러 page에 걸쳐 섞이는 경우에는 현재 `N+1` 완화만으로 부족할 수 있다.
- 향후 sequence smoothing이나 ML classifier를 결합하면 boundary 후처리와 충돌하지 않도록 우선순위를 다시 검토해야 한다.
