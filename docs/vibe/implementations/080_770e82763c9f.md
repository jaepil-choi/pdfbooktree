## 변경 배경

- 고정 corpus 감사에서 heading 추론 결과에 표 행, 이미지 placeholder, 맨숫자, 단일 토큰이 level 1로 섞여 나왔다. 기존 config knob을 아무리 돌려도 개선되지 않았고, `typography.max_heading_tier` 감소는 오히려 악화하는 경우가 있었다.
- 실험 117에서 원인을 특정했다. OCR overlay는 invisible text를 단일 font로 쓰고 각 줄의 font size를 그 줄의 bbox에 맞춰 정한다. 표본 8권 전부 font 1종, `font_size`와 bbox height의 상관계수 0.9988~1.0, 그리고 책마다 다른 값에서 clamp된다. 즉 `font_size`는 조판 정보가 아니라 OCR box 기하이고, 그 위에서 절대 크기나 tier 번호는 책 사이에서 의미가 달라진다.
- 처음에는 overlay가 남긴 `![image](...)`와 표 pipe를 근거로 쓰려 했으나, 그것은 Upstage document parse 전용 표시라 다른 OCR overlay에는 없다. 라이브러리는 사용자가 가져온 overlay를 given으로 받아야 하므로 이 경로는 폐기했다.
- 실험 118에서 질문을 바꿨다. "어떤 기본값이 최적인가"가 아니라 "agent가 조절할 수 있는 축인가"다. 표본 6권 전부 말이 되는 지점에 도달했지만 **여섯 권이 서로 다른 설정에서** 도달했다. 단일 기본값으로는 맞출 수 없고 조절 가능성이 답이라는 뜻이다.

## 결정 내용

- 새 knob은 전부 책 내부 상대값으로 정의했다. 절대 font size와 tier 번호는 책마다 뜻이 달라져 agent가 쓸 수 없다.
- `max_headings_per_page`는 페이지 내 희소성 축이다. 실측상 최상위 size class 줄이 페이지에 1~3개면 장 시작, 7개 이상이면 그림·배너 페이지였다. 이 신호는 어떤 overlay든 주는 일반 정보다.
- `size_class_depth`는 상위 size class 개수로, tier 번호를 쓰는 `max_heading_tier`를 대체하는 해석 가능한 축이다.
- 두 knob 모두 기본값 0(off)으로 두었다. 목표는 더 나은 기본값이 아니라 틀렸을 때 싸게 고칠 수 있는 것이므로, 기존 선택 결과를 바꾸지 않는 것이 전제다.
- `large_font_tier`와 `large_height_tier`는 같은 측정이다. 두 tier set의 최상위가 표본 전체에서 100% 동일했다. 독립 증거 두 개로 취급하던 것을 제거하고 font tier만 남겼다.
- `inspect sweep`은 typography 분석을 한 번만 하고 설정을 메모리에서 훑는다. 싸고 결정적인 것이 이 도구의 존재 이유이므로 설정마다 전체 export를 돌리지 않는다.
- skill은 단일 원본에서 두 target을 렌더링한다. agents target은 전체 지침, Claude target은 저장소의 `CLAUDE.md`가 `AGENTS.md`에 위임하는 것과 같은 adapter다. adapter에도 frontmatter의 `name`과 3인칭 `description`, workflow 요약을 넣어 progressive disclosure의 첫 단계가 Claude 쪽에서도 성립하게 했다. 본문은 복제하지 않는다.

## 작동 방식

- geometry heading 선택 경로에서 두 knob이 후보 집합을 좁힌다. 둘 다 0이면 선택 결과가 이전과 동일하다.
- `pdfbooktree inspect sweep <PDF>`는 설정별 후보 수, 후보가 있는 page 수, page당 후보 간격을 표로 낸다. agent는 이 표만 보고 어느 방향으로 밀지 정한 뒤 `process --set typography.max_headings_per_page=...`로 재실행하고 `inspect markdown`으로 확인한다.
- `pdfbooktree skill install`은 `.agents/skills/use-pdfbooktree/`에 8개 파일을, `.claude/skills/use-pdfbooktree/`에 adapter 1개를 쓴다.

## 대안과 제외한 선택지

- overlay가 남긴 `![image](`와 표 pipe로 비산문을 거르는 안은 Upstage 전용이라 배제했다. 라이브러리는 사용자의 overlay를 given으로 받아야 한다.
- 크기 축을 더 잘게 잘라 tier를 정교화하는 안도 배제했다. clamp 위에서는 height가 1종뿐이라 크기 축 자체에 정보가 남아 있지 않다.
- 하나의 개선된 heading 알고리즘을 기본값으로 삼는 안을 배제했다. 6권이 서로 다른 설정을 요구했으므로 단일 기본값은 overfitting이다.
- Claude target에 전체 본문을 복제하는 안도 배제했다. 원본이 둘이 되면 반드시 어긋난다.

## 남은 리스크

- `max_headings_per_page`는 하드 게이트라 배너 요소가 페이지마다 반복되는 책에서는 유효 후보까지 함께 떨어질 수 있다. 그런 책은 sweep 표에서 포화 구간으로 드러나며 agent가 다른 축으로 옮겨야 한다.
- 두 knob의 기본값이 off이므로 아무것도 하지 않으면 기존 품질 그대로다. 개선은 agent가 조절해야 발생한다.
- `inspect sweep`의 sweep 격자는 코드에 고정돼 있다. 격자 밖 설정이 필요한 책은 `--set`으로 직접 지정해야 한다.
- Claude adapter가 agents target을 상대 경로로 가리키므로 두 디렉터리를 함께 배포해야 한다. 한쪽만 복사하면 링크가 끊긴다.
