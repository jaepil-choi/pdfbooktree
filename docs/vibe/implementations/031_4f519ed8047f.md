## 변경 배경

- 기존 production runtime은 `toc/`와 `alignment/`를 중심으로 동작했다. 처리 흐름은 TOC page 탐지, TOC item parsing, printed page offset 추정, 본문 heading matching을 거쳐 bookmark 후보를 만드는 구조였다.
- 최근 제품 방향은 TOC page parsing을 기본 전략으로 두지 않고, 책 전체 typography 신호에서 heading hierarchy를 직접 복원하는 쪽으로 바뀌었다. 따라서 TOC page 탐지와 printed page alignment를 기본 runtime에 남겨 두면 코드 구조와 제품 판단이 계속 어긋난다.
- 사용자는 `toc_pages`와 typography 기반 방법이 결국 같은 hierarchical bookmark plan으로 수렴해야 한다는 점을 지적했고, 이후 공통 단계는 `outline`과 `export`로 분리해야 한다고 결정했다.
- 패키지 구조도 임시 구현 이름이나 동사 중심 디렉터리보다 domain boundary가 드러나는 형태가 필요했다. 그 결과 `typography`, `outline`, `pdf`, `export`, `ocr`, `utils`만 남기는 ground-up rebuild를 진행했다.

## 결정 내용

- `toc/`, `alignment/`, `metrics/`, 기존 `output/` 패키지를 제거했다. TOC page detection, TOC item extraction, offset alignment, TOC 평가 코드는 더 이상 runtime `src`에 두지 않는다.
- 새 runtime 경계는 다음으로 정했다.
  - `typography/`: PDF span을 visual line으로 재군집화하고 font size / bbox height tier, heading 후보를 만든다.
  - `outline/`: heading 후보 sequence를 `BookmarkPlanItem`으로 변환하고 plan을 검증하며 tree로 변환한다.
  - `pdf/`: PDF text와 outline을 읽고 쓰는 low-level adapter다.
  - `export/`: 공통 bookmark plan을 최종 산출물인 bookmarked PDF와 Markdown tree로 내보낸다.
  - `ocr/`: Upstage Document Parse 기반 OCR overlay 전처리 기능으로 유지한다.
- `Processor`는 TOC 없이 typography pipeline을 기본 실행한다. 기존 outline이 있고 `skip_existing_bookmarks=True`이면 outline을 reference plan으로 변환해 Markdown만 export하고 PDF outline overwrite는 건너뛴다.
- OCR 패키지는 유지하되 EasyOCR/PaddleOCR placeholder 파일과 registry 분기를 제거했다. 현재 runtime에서 지원하는 OCR engine은 Upstage 하나로 좁혔다.
- `pyproject.toml`과 `uv.lock`에서 TOC/ML/LLM 경로에 쓰던 의존성을 제거했다. 남긴 runtime 의존성은 PyMuPDF, numpy, OCR overlay, httpx, typer/rich, dotenv/truststore 중심이다.
- 테스트도 새 구조에 맞춰 재작성했다. TOC/offset/LLM 테스트는 제거하고 typography line merge, tiering, heading candidate, Processor export, existing outline export, batch 흐름을 검증한다.

## 작동 방식

- `Processor.run()`은 먼저 입력 PDF의 page count와 기존 outline을 확인한다.
- 기존 outline이 있고 skip 정책이 켜져 있으면 `pdf.outline.outline_to_plan()`으로 공통 `BookmarkPlanItem` 목록을 만든 뒤 `export.markdown.export_markdown_tree()`만 실행한다.
- 새 typography 경로는 다음 순서로 동작한다.
  1. `typography.lines.extract_typography_lines()`가 PyMuPDF span을 page 전체에서 모은 뒤 y 중심 좌표로 visual line을 다시 묶는다.
  2. line 대표 `font_size`와 `height`는 span 값의 median을 사용한다.
  3. `typography.tiers.compute_tier_set()`이 `font_size`와 `height`를 각각 tiering한다. KDE/unique value 기반 cut, 가까운 tier merge, 최소 count merge를 적용한다.
  4. `typography.headings.extract_heading_candidates()`가 상위 tier, page 상단 위치, 번호 패턴, bold 여부를 evidence로 heading 후보를 만든다.
  5. `outline.infer.infer_outline()`이 후보 sequence를 `BookmarkPlanItem`으로 변환한다. 번호 깊이가 있으면 우선하고, 없으면 font/height tier를 사용한다.
  6. `outline.validate.validate_bookmark_plan()`이 빈 plan, page range, level jump, page order를 검증한다.
  7. 검증이 통과하면 `export.pdf.export_bookmarked_pdf()`가 PDF outline을 삽입한 사본을 만들고, `export.markdown.export_markdown_tree()`가 `toc.json`, `toc.md`, node별 `index.md`를 만든다.
- 모든 public/intermediate page number는 기존 규칙대로 1-based PDF page를 사용한다.
- artifact는 `whole_book_lines.jsonl`, `font_size_tiers.json`, `height_tiers.json`, `heading_candidates.json`, `bookmark_plan.json`, `bookmark_plan_validation.json`로 저장한다.

## 대안과 제외한 선택지

- `strategies/book_hierarchy.py` 같은 전략 패키지는 제외했다. 현재 제품 방향은 여러 runtime 전략을 병렬 유지하는 것이 아니라 typography 기반 primary runtime으로 단순화하는 것이기 때문이다.
- `fontsize/` 패키지명도 제외했다. 실제 추론은 font size뿐 아니라 bbox height, visual line, bold, page position까지 다루므로 domain name으로는 `typography`가 더 정확하다.
- `markdown/export.py` 구조는 제외하고 `export/markdown.py`를 선택했다. Markdown은 domain이 아니라 최종 export format이므로 `export` 아래에 두는 편이 책임 경계가 명확하다.
- TOC 코드를 fallback으로 src에 남기는 선택지는 제외했다. 남겨 두면 `Processor`, config, CLI에 TOC 전용 개념이 계속 흘러 들어와 단순화 목적을 해친다.
- EasyOCR/PaddleOCR placeholder는 제거했다. 실제 동작하지 않는 provider 파일보다 Upstage만 명시적으로 지원하는 구조가 현재 runtime을 더 분명하게 만든다.

## 남은 리스크

- typography heading extraction은 아직 deterministic heuristic이다. 실제 책에서는 running header, 수식 조각, 표 제목, chapter decorative number가 heading 후보에 섞일 수 있다.
- font size와 height signal selection은 아직 단순 병렬 산출이다. 어떤 signal이 더 신뢰할 만한지 자동 선택하는 confidence 모델은 후속 작업이 필요하다.
- Markdown export는 plan page range의 text를 단순 추출해 붙인다. 본문 품질, section별 정확한 종료 범위, 이미지/표 보존은 아직 다루지 않는다.
- `ocr_policy`는 config에 남아 있지만 Processor 자동 OCR overlay와는 아직 연결되지 않았다. 현재 OCR overlay는 CLI/API로 별도 실행해야 한다.
- TOC fallback 연구 코드를 src에서 제거했기 때문에, 나중에 다시 필요하면 experiments나 별도 branch에서 검증한 뒤 공통 `BookmarkPlanItem` 출력 계약에 맞춰 재도입해야 한다.
