## 변경 배경

- `outputs/300study_detection.json`의 pseudo label을 검토하면서 book이 아닌 짧은 PDF와 잘못된 bookmark가 dataset에 섞일 수 있음을 확인했다.
- 기존 결과 기준 bookmark 보유 PDF 412개 중 50페이지 미만 PDF가 8개 있었고, 이런 문서는 TOC page detector 학습용 pseudo label로 쓰기보다 제외하는 편이 낫다고 판단했다.
- 사용자가 page 수가 50페이지 미만인 경우는 아예 skip하도록 요청했다.

## 결정 내용

- `BookmarkTocBatchDetector`에 `min_total_pages` 옵션을 추가하고 기본값을 50으로 설정했다.
- `detect-bookmark-toc` CLI에도 `--min-total-pages` 옵션을 노출했다.
- batch result에는 `min_total_pages`와 `skipped_short_pdf_count`를 추가해 몇 개의 짧은 PDF가 제외됐는지 결과 JSON과 CLI 요약에서 확인할 수 있게 했다.
- worker 함수에서 PDF page count를 먼저 확인하고, threshold 미만이면 bookmark 추출과 TOC 탐지 전에 `skipped_short`로 반환하게 했다.

## 작동 방식

- `_process_pdf_for_bookmark_toc`는 먼저 `fitz.open`으로 `total_pages`를 읽는다.
- `total_pages < min_total_pages`이면 bookmark 여부와 무관하게 처리 결과에 넣지 않고 skip count만 증가시킨다.
- 기존 `skipped_no_bookmark_count`와 구분하기 위해 `_handle_processed_item`은 `(skipped_no_bookmark, skipped_short_pdf)` tuple을 반환한다.
- 기존 테스트 fixture는 50페이지 미만 PDF를 사용하므로, 기존 탐지 동작을 검증하는 테스트에는 `min_total_pages=1`을 명시했다.
- 새 테스트는 기본값 50에서 짧은 PDF가 제외되고 긴 PDF만 결과에 들어가는지 검증한다.

## 대안과 제외한 선택지

- 짧은 PDF를 `not_detected` result로 남기는 방식은 제외했다. 사용자가 "아예 skip"을 요청했고, 학습 dataset의 분모와 실패/미탐지 통계에 섞이지 않는 편이 더 명확하다.
- bookmark 추출 이후에 page 수 필터를 적용하는 방식은 제외했다. 짧은 PDF는 학습 대상이 아니므로 bookmark 파싱 비용과 오류 가능성을 먼저 감수할 이유가 없다.
- threshold를 하드코딩하는 방식은 제외했다. 기본값은 50으로 두되, 실험이나 재현 테스트에서 낮출 수 있도록 CLI와 class 옵션으로 열어두었다.

## 남은 리스크

- 50페이지 기준은 현재 데이터셋 관찰과 사용자의 판단에 따른 휴리스틱이다. 짧지만 실제 book인 PDF는 제외될 수 있다.
- bookmark 자체가 잘못 들어간 긴 PDF는 여전히 남는다. 후속으로 bookmark tree depth, bookmark count 분포, confidence/vote 기반 필터를 추가 검토해야 한다.
- histogram 이미지는 `outputs/` 아래 생성된 분석 산출물이라 저장소 규칙상 커밋하지 않았다.
