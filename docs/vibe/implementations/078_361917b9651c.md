## 결정 내용

- 진단은 `markdown_manifest.json`만 읽는다. node 본문 파일은 열지 않는다. manifest에 node별 level, page span, word_count, source와 coverage, validation이 모두 있어 충분하고, 계층 경계를 깨지 않는다.
- verdict는 `ok`, `thin`, `over_split`, `fragmented`, `uncovered`, `duplicated`, `invalid_graph` 일곱 가지다. 각 finding은 code, severity, 관측 수치를 담은 detail, cause를 갖는다.
- 임계값은 책·파일명·출판사와 무관한 비율과 절대 수로만 정의하고, 고정 corpus 335개 manifest의 실제 percentile로 보정했다(실험 114). unassigned_ratio 0.10은 실측 p90 0.03·p95 0.048 위, pages_per_node 평균 50은 실측 median 10.0·p75 15.7 위, fragment_ratio 0.30은 실측 median 0.167·p75 0.317 위에 둔다.
- 재시도 후보는 추측하지 않고 전부 실측했다. 효과가 확인되지 않은 override는 제시하지 않는다. `typography.max_heading_tier` 감소는 5권 중 3권 무효·2권 악화로 확인돼 후보에서 뺐다.
- 재시도 후보는 `command` 문자열과 함께 shell을 거치지 않는 `command_argv`를 낸다. corpus 파일명 335개 중 72개가 공백·괄호·대괄호를 포함해, 문자열만으로는 shell에 따라 깨지기 때문이다.
- 같은 감사에서 드러난 제품 결함은 각각 가장 좁은 subsystem에서 고쳤다. 공개 API·config schema·기본값은 바꾸지 않았다.

## 작동 방식

- `inspect_markdown_tree(target)`는 output directory 또는 manifest 경로를 받아 manifest를 찾고, source·graph·levels·words_per_node·pages_per_node·coverage·sources·titles·validation을 요약한 뒤 finding을 만든다. verdict는 `invalid_graph` > `uncovered` > `thin` > `over_split` > `fragmented` 순의 가장 심각한 finding이다.
- cause는 관측에서 결정한다. thin이면서 모든 node source가 `existing_outline`이면 `reused_existing_outline`, 아니면 `sparse_heading_candidates`다. 이 구분이 재시도 방향을 가른다.
- word 신호가 없는 export를 위해 `_words_per_node_stats`는 `has_data`를 함께 낸다. tree export는 node word_count를 남기지 않으므로, 이 값이 없으면 word 기반 over_split 조건을 평가하지 않고 그 사실을 결과에 남긴다. 평가했다면 `markdown.enabled=false`인 모든 run이 품질과 무관하게 over_split이 됐을 것이다.
- `content_mode=inclusive`는 부모와 자식의 page 중복을 설계상 허용하므로, 중복은 `uncovered`와 분리된 `duplicated` finding이며 inclusive에서는 발화하지 않는다.
- `thin`과 `over_split`은 상호배타로 처리한다. 동시에 나오면 "후보를 늘려라"와 "줄여라"가 함께 제시돼 루프가 수렴하지 않는다.
- `inspect compare`는 입력을 한 번만 읽어 plan JSON과 Markdown manifest를 자동 dispatch한다. 손상된 파일은 plan 경로로 흘리지 않고 즉시 입력 오류로 보고한다.
- typography tier: `_cluster_by_density`가 인접 peak 사이마다 최소 밀도 지점을 cut으로 골라 `len(cuts) == len(peaks) - 1`을 보장한다. 이전에는 valley 검출이 cut을 빠뜨려 `_build_tiers`가 IndexError를 냈다.
- outline level: `normalize_bookmark_plan`이 active raw tier stack을 유지하며 연속 depth로 재매핑한다. 같은 raw tier는 sibling depth를 지키고 상위 tier가 다시 나오면 올바른 조상 depth로 복귀한다. synthetic 항목은 만들지 않는다.
- 기존 outline: `resolve_existing_outline_action`이 `outline_to_plan` 결과를 authoritative validator로 검사해, 구조가 깨졌으면 low-quality 교체 설정과 무관하게 재사용을 거부한다. 거부 사유는 `ExistingOutlineDecision`에 실려 처리 warning, log event, review summary로 드러난다.
- heading fallback: strict geometry 후보가 비었을 때만 기존 evidence 기반 후보를 page당 하나씩 결정론적으로 고른다. 순위는 numbering, top position, bold, confidence, y0, 제목 순이다. 후보는 `BpeHeading` 계약으로 변환해 넘긴다. 이 변환을 빠뜨렸을 때 `review._candidate_index`가 `candidate.source`를 읽다 AttributeError로 죽었다.
- 모든 page 값은 1-based를 유지한다.

## 대안과 제외한 선택지

- 저품질 기존 outline을 기본적으로 재추론하도록 `outline_quality` 기본값을 바꾸는 안은 공개 default semantics 변경이라 제외했다. 대신 구조가 깨진 경우만 무조건 거부하고, 품질 문제는 진단과 재시도 후보로 노출한다.
- typography 후보 선택과 outline hierarchy를 함께 재설계하는 안은 두 subsystem을 동시에 건드려 제외했다. fragment 문제는 이 범위에서 해결되지 않으므로 알려진 한계로 표기했다.
- 빈 plan을 synthetic root 하나로 채워 validation만 통과시키는 방식은 실패를 숨기므로 배제했다. evidence가 전혀 없으면 빈 결과를 그대로 둔다.
- 잘못 나뉜 결과를 진단 단계에서 자동 보정하는 안도 배제했다. 진단은 읽기 전용이어야 하고, 교정은 agent가 parameter로 다시 실행하는 것이 이 제품의 루프다.
- `shlex.quote`만으로 명령 문자열을 안전하게 만드는 안은 POSIX 전용이라 cmd.exe에서 깨진다. 문자열은 유지하되 shell을 거치지 않는 argv를 함께 제공하는 쪽을 택했다.

## 남은 리스크

- fragment heading은 현재 parameter로 신뢰성 있게 교정되지 않는다. `heading_candidate_mode=position_and_font`가 표본 5권 중 2권에서만 부분 개선했고, fragment는 깊은 level이 아니라 level 1에 가장 몰려 있어(0.33 대 0.296 대 0.23) split level 조정으로도 줄지 않는다. 진단은 이를 숨기지 않고 알려진 한계로 보고한다.
- fragment 판정의 단어 인식은 한글과 라틴 문자만 본다. 한자나 가나만으로 된 제목은 `no_word`로 분류될 수 있다. 임계값 보정도 같은 규칙 위에서 이뤄졌다.
- `pages_per_node`의 mean은 page_count/node_count이고 median과 max는 node span 통계라 정의가 다르다. thin과 over_split 판정은 mean만 사용한다.
- `typography.min_tier_gap`은 이제 소비자가 없는 공개 config key다. 공개 schema와 golden contract를 건드리므로 이번 범위에서 다루지 않았다.
- 고정 corpus의 validation 분할 71권은 공개하지 않았다. 이 커밋의 주장은 development 증거와 실제 실행 검증에 한정된다.
