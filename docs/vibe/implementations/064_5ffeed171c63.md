  못했다. 또한 parent가 descendant page text까지 포함해 계층이 깊을수록 같은
  본문이 여러 파일에 반복됐다.

  후보 graph는 YAML 오류, dangling link, 관계 비대칭, 중복 page가 모두 0개였다.
- 릴리스 전 요구사항은 자동 quality score보다 agent가 TOC, node metadata와
  evidence를 필요한 만큼 따라가는 progressive disclosure 구조를 우선한다.

## 결정 내용

- 기본 tree export를 `<stem>_markdown/nodes/` 아래의 flat Markdown graph로
  변경했다. node ID는 plan 순서 기반 `n0001`, 파일명은
  `NNNN_L<level>_p<page>_<slug>.md` 형식이라 전체 output에서 고유하고
  결정론적이다.
- 각 node와 `toc.md`는 PyYAML `safe_dump()`로 첫 줄부터 표준 front matter를
  생성한다. title 원문은 metadata에 보존하고 filename만 Windows reserved name,
  금지 문자, trailing dot/space와 길이를 고려해 sanitize한다.
- 기본 `processing.markdown_content_mode`는 `direct`다. 다음 bookmark 시작 전까지의
  page만 현재 node가 소유한다. 기존 subtree 중복 방식은 명시적 `inclusive`
  호환값으로 남겼다.
- 같은 PDF page에서 bookmark가 연속되면 plan상 마지막 item이 page text를
  소유한다. 앞선 item은 navigation-only node가 되며 같은-page boundary 목록을
  manifest warning으로 남긴다. page 안의 heading 위치를 알 수 없는 현재 plan
  계약에서 중복 없이 결정적인 결과를 만드는 정책이다.
- graph root에 node ID가 포함된 `bookmark_plan.json` snapshot을 항상 생성한다.
  따라서 `write_artifacts=false`여도 node의 `evidence_ref`가 유효하다. 기존 plan의
  `source`, `confidence`, `evidence` 값은 의미를 바꾸지 않고 보존한다.
- tree와 split 결과를 `MarkdownExportResult`로 통일하고 `export_mode`로 구분했다.
  `process`, `apply`, `Processor`와 batch item run은 graph manifest를
  `artifact_paths.markdown_manifest`로 연결한다.

## 작동 방식

- `export_markdown_tree()`는 `markdown_graph.export_markdown_graph()`에 plan과
  `total_pages`, content mode를 전달한다. exporter는 plan을 한 번 순회해 node ID,
  논리적 page 범위, 직접 본문 범위와 parent/children/previous/next 관계를 만든다.
- PDF text를 1-based page dictionary로 읽고 node별 Markdown, root TOC와 plan
  snapshot을 기록한 뒤 graph validation을 수행한다. YAML parse, node/path 중복,
  dangling wiki link, 관계 대칭성, TOC 도달성, page coverage와 결정성을 검사한다.
- validation을 통과하면 input/plan hash, node mapping, coverage, warning과 validation
  결과를 `markdown_manifest.json`에 기록하고 `MarkdownExportResult`로 반환한다.
  내부 불변식이 깨지면 실패 manifest를 남긴 뒤 `RuntimeError`로 처리한다.
- `apply_plan()`과 기존 outline fast path 모두 tree 결과의 `output_dir`와
  `manifest_path`를 사용한다. CLI와 `Processor`가 만든 `ProcessingResult`에는 같은
  `MarkdownExportResult`와 manifest artifact 경로가 들어가므로 report와 immutable
  run manifest가 동일한 계약을 노출한다.

## 대안과 제외한 선택지

- 기존 중첩 directory와 `index.md`를 유지하는 안은 basename 모호성과 Windows 경로
  길이를 해결하지 못해 제외했다. 계층은 filesystem 대신 명시적 graph 관계로
  표현한다.
- same-page node마다 같은 page text를 복제하는 안은 direct mode의 핵심인 중복 제거를
  깨므로 제외했다. heading geometry를 이용한 page 내부 분할은 현재 bookmark plan에
  위치 정보가 없어서 후속 과제로 남겼다.
- 기존 outline의 confidence를 `null`로 바꾸는 안은 원 plan 값을 변형하므로 제외했다.
  대신 manifest에서 confidence가 내용 품질의 합격 확률이 아님을 명시했다.
- length-limited split은 선택된 level의 일부 경계만 파일로 만들기 때문에 모든 plan
  node 관계를 그대로 연결할 수 없다. 이번 커밋에서는 기존 split 동작을 유지하고
  `export_mode=split`로만 구분했다.

## 남은 리스크

- same-page sibling이 여러 개면 마지막 item이 page 전체를 소유하므로 page 내부의
  앞선 section text가 의미상 뒤 node에 포함될 수 있다. manifest warning을 review
  signal로 사용해야 한다.
- length-limited split을 graph metadata와 통합하는 설계, 실제 Obsidian vault
  showcase와 agent review summary/item artifact는 별도 phase가 필요하다.
- 실행 중인 `.venv\\Scripts\\pdfbooktree.exe` PID 48892가 Windows 파일 잠금을 잡고
  있어 일반 `uv sync`를 완료하지 못했다. `pyproject.toml`과 `uv.lock`은 PyYAML을
  포함하며 테스트는 `--no-sync --with pyyaml` overlay로 검증했다. 프로세스 종료 후
  `uv sync`를 다시 실행해야 한다.
- 릴리스 전에 기존 전체 Ruff baseline 문제를 별도 정리해야 한다.
