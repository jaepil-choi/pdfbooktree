## 변경 배경

- 기존 OCR text layer가 깨진 scanned PDF에서는 TOC 탐지와 font/height hierarchy 추론이 모두 GIGO로 무너진다.
- 최근 Document Parse overlay 실험에서 기존 PDF text layer를 이어받지 않고 page image 위에 새 invisible text layer를 올리는 방식이 검색 가능한 PDF를 만들 수 있음을 확인했다.
- OCR provider는 Upstage, PaddleOCR, EasyOCR 등으로 바뀔 수 있으므로, 제품 코드는 provider raw output이 아니라 표준 삽입 모델을 기준으로 동작해야 한다.

## 결정 내용

- `pdfbooktree.ocr` 서브패키지를 새로 만들고 `OcrOverlayBuilder`와 `OcrOverlayConfig`를 public API로 노출했다.
- OCR engine은 전략 객체로 분리했다. 이번 구현에서는 `upstage`만 실제 동작하고, `paddle`과 `easyocr`는 placeholder 주석 파일만 둔다.
- provider adapter는 raw OCR response를 `InsertableOcrPage` / `InsertableOcrElement` / `InsertableOcrLine` / `InsertableOcrWord`로 변환한다.
- 기존 bookmark가 있는 PDF는 confirmation 없이 OCR overwrite를 실행하지 않는다. `confirm_bookmark_ocr_overwrite=True` 또는 CLI `--confirm-bookmark-ocr-overwrite`가 없으면 `ExistingBookmarkConfirmationRequired`를 발생시킨다.
- `verify.py`와 `quality.py`는 만들지 않았다. 대신 후속 hierarchy 추론 입력으로 바로 쓸 수 있는 `stats.py`를 만들었다.
- `ocrmypdf` renderer를 사용하되, 제품 코드는 `InsertableOcrPage`만 보고 invisible text layer를 생성한다.
- Upstage API 호출은 Windows 사내 TLS 체인에서도 검증을 끄지 않고 동작하도록 `truststore.SSLContext`를 명시적으로 사용한다.

## 작동 방식

- `OcrOverlayBuilder.run()`은 입력 PDF page를 렌더링한 뒤 engine registry에서 선택한 OCR engine을 호출한다.
- raw response cache key는 입력 PDF hash, 1-based page, render DPI, engine, request params를 포함한다.
- insertable cache key는 raw response hash와 adapter version을 포함한다. adapter가 바뀌어도 API 재호출 없이 표준 모델을 다시 만들 수 있게 하기 위함이다.
- Upstage adapter는 `content.text`와 word join을 비교해 overlay mode를 정한다.
  - 일치하면 word-level overlay를 사용한다.
  - table처럼 content row 수와 시각 row 수가 맞으면 row-level overlay를 사용한다.
  - equation처럼 row 매칭이 어려우면 whole-element overlay를 사용한다.
- output PDF는 원본 page content stream을 복사하지 않고, 렌더링된 page image와 새 invisible text layer로 구성한다. 따라서 기존 OCR text layer와 기존 bookmark는 output PDF에 복사되지 않는다.
- stats artifact는 `ocr_page_stats.jsonl`, `ocr_element_stats.jsonl`, `ocr_line_stats.jsonl`를 기본 생성하고, 옵션으로 `ocr_word_stats.jsonl`를 생성한다.
- line stats에는 bbox height, median word height, inserted font size, page position, numbering depth, category, overlay mode를 기록한다.

## 대안과 제외한 선택지

- `engines/document_parse.py`처럼 provider-neutral한 파일명은 쓰지 않았다. engine 구현체는 실제 provider 이름을 드러내는 것이 교체 가능한 전략 구조를 더 명확하게 만든다고 판단했다.
- PaddleOCR와 EasyOCR 구현은 이번 커밋에서 제외했다. 실험 비교 대상이었지만 v0.1 제품 경로는 Upstage Document Parse를 먼저 안정화하는 것이 목적이다.
- 주관적 quality score는 만들지 않았다. 검사자가 없는 점수보다 font/height hierarchy에 바로 먹일 수 있는 stats가 더 유용하다고 판단했다.
- SSL 문제를 `verify=False`로 우회하지 않았다. 기존 실험 패턴과 동일하게 OS trust store를 사용하는 방식만 허용했다.

## 남은 리스크

- `ocrmypdf` renderer가 한국어 glyph font 경고를 낼 수 있다. invisible text 자체는 검색/복사 가능하지만 viewer highlight 표시가 빈 칸처럼 보일 수 있다.
- Upstage API 비용과 latency가 있으므로 cache가 필수다. 대량 책 처리 전에는 page range 실행과 cache 재사용을 먼저 확인해야 한다.
- inserted font size는 overlay renderer가 bbox에 맞춰 만든 값이므로 원본 책의 실제 font size와 동일하다고 보면 안 된다. hierarchy 추론에서는 bbox height와 함께 보조 신호로 써야 한다.
- 이번 커밋은 OCR overlay 전처리만 추가했고, 기존 `Processor` main pipeline에는 아직 연결하지 않았다.
