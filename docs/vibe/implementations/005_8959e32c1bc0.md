## 변경 배경

- 기존 bookmark가 있는 PDF에서는 bookmark title이 TOC page text에 반복해서 등장하므로 TOC page 복원에 강한 기준 신호로 쓸 수 있다.
- 이전 구현의 `offset_consistency`는 bookmark target PDF page와 TOC line 끝 숫자의 차이만 보았다.
- 실제 OCR text layer에서는 TOC의 printed page number가 line 끝에 안정적으로 남지 않거나, window 내부의 다른 위치에 숫자로 남을 수 있다.
- 따라서 line-final page number에 한정하지 않고 page text window 안의 standalone 숫자 후보들을 함께 보아야 한다.

## 결정 내용

- `toc.features.extract_page_number_candidates()`를 추가해 text 안의 standalone 1-2000 숫자를 순서대로 추출한다.
- bookmark matching window에는 기존 `trailing_number`와 함께 `number_candidates`를 저장한다.
- `score_offset_consistency()`는 각 match의 모든 숫자 후보에 대해 `bookmark_target_pdf_page - number` offset을 계산한다.
- 같은 page 안에서 같은 offset이 여러 bookmark 항목에 의해 반복되면 강한 신호로 판단한다.
- 숫자 후보가 늘어나면서 chapter 번호나 section 번호 같은 noise도 늘어날 수 있으므로, 단순 후보 개수가 아니라 같은 modal offset을 지지한 서로 다른 bookmark order 수를 핵심 기준으로 삼았다.
- 기존 public interface는 바꾸지 않았다. `detect_toc_pages_from_bookmarks()`의 반환 구조와 호출 방식은 유지하고, candidate row의 `offset_consistency_score` 의미만 더 넓혔다.

## 작동 방식

- `build_page_windows()`가 page line window를 만들 때 raw text에서 `number_candidates`를 추출한다.
- `match_bookmarks_to_pages()`는 bookmark title과 window text가 fuzzy match되면 match evidence에 `number_candidates`를 함께 남긴다.
- `score_offset_consistency()`는 match별 bookmark target PDF page와 숫자 후보들의 offset을 계산한다.
- page별 modal offset을 찾은 뒤, 그 offset을 지지한 bookmark order가 2개 이상일 때만 점수를 부여한다.
- 점수는 `modal_bookmark_count * (0.75 + 0.25 * modal_share)`로 계산한다. 이 방식은 같은 offset을 지지한 bookmark 개수를 우선하고, 후보 숫자 전체에서의 share는 보조 가중치로만 사용한다.
- `OFFSET_CONSISTENCY_VOTE_THRESHOLD`는 1.5로 두어 서로 다른 bookmark 2개가 같은 offset을 지지하면 `offset_consistency` voter가 켜질 수 있게 했다.
- 모든 PDF page number는 기존 package 규칙대로 1-based로 유지한다.

## 대안과 제외한 선택지

- line-final number만 유지하는 방법은 제외했다. OCR/layout이 TOC page number를 줄 끝에 보존하지 않는 경우를 설명하지 못한다.
- page 전체 숫자를 title match 없이 전부 offset 계산에 쓰는 방법은 제외했다. 본문 page나 running header의 숫자까지 섞여 false positive가 커질 수 있다.
- modal offset의 후보 수만으로 점수화하는 방법은 제외했다. 한 bookmark window에 숫자가 많이 들어간 경우 한 항목이 점수를 과도하게 키울 수 있기 때문이다.
- `PageFeature` dataclass에 bookmark 기반 feature를 넣는 방법은 제외했다. bookmark-guided detector는 평가용 보조 경로이고, bookmark 없는 runtime detector의 objective feature와 섞이면 입력 계약이 흐려진다.

## 남은 리스크

- standalone 숫자 후보에는 chapter 번호나 part 번호가 포함될 수 있다. 현재는 여러 bookmark order의 modal offset 반복으로 억제하지만, PDF별 OCR 상태에 따라 noise가 남을 수 있다.
- roman numeral printed page number는 아직 offset consistency 후보에 포함하지 않는다.
- candidate row에는 score만 남기고 modal offset 자체와 evidence 개수는 저장하지 않는다. 이후 디버깅이 필요하면 중간 산출물에 modal offset과 supporting bookmark order를 추가할 수 있다.
- 이 기능은 기존 bookmark가 있는 PDF의 silver label 복원과 detector 평가 보조용이다. bookmark가 없는 일반 처리 경로의 primary TOC detection에는 사용하지 않는다.
