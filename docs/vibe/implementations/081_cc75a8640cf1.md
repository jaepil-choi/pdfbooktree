# 구현 노트: fix: apply the page cap in every heading candidate mode

## 메타데이터

- 구현 커밋: `cc75a8640cf1`
- 직전 구현 커밋: `770e82763c9f`
- 노트 생성 일시: `2026-08-18`

## 변경 배경

- 직전 커밋에서 추가한 `typography.max_headings_per_page`가 `select_geometry_headings`의 font 후보 집합(`font_ids`)에만 적용돼 있었다.
- `heading_candidate_mode`가 `position`이면 최종 선택은 `position_ids`라서 상한이 적용된 집합을 아예 쓰지 않는다. 실측으로 같은 책에서 값을 0, 1, 3으로 바꿔도 plan이 276개로 고정이었다. 오류도 경고도 없이 무반응이었다.
- 이 저장소는 두 커밋 전에 소비자가 없던 공개 config key `typography.min_tier_gap`을 같은 이유로 제거했다. agent가 값을 바꿔도 결과가 같은 knob은 재시도 예산을 낭비시키고 잘못된 인과를 학습시킨다. 새로 추가한 knob이 같은 함정에 빠지는 것은 스스로 세운 기준을 어기는 것이다.
- 이 결함은 구현 lane이 스스로 리스크로 보고했고, 통합 검증에서 mode별로 실제 값을 넣어보며 확인했다. 테스트 430개는 통과하고 있었기 때문에 테스트만으로는 드러나지 않았다.

## 결정 내용

- 상한을 mode 분기보다 뒤로 옮겨 최종 `selected_ids`에 적용했다. knob의 의미가 "한 page가 낼 수 있는 후보 수 상한"이므로 mode에 따라 달라질 이유가 없다.
- 대안으로 `position` mode와의 조합을 config 단계에서 거부하는 방법도 있었으나 배제했다. 조합을 막는 것보다 knob이 선언한 의미대로 동작하는 편이 agent에게 예측 가능하다.
- 기본값 0은 그대로 두어 아무 필터도 걸리지 않는다.

## 작동 방식

- `select_geometry_headings`는 먼저 mode에 따라 `selected_ids`를 정하고, 그다음 `max_headings_per_page > 0`이면 page별로 후보 수를 세어 상한을 넘는 page의 후보를 통째로 제외한다.
- 같은 책에서 mode별 반응은 다음과 같다. `font`는 16/14/16, `position`은 수정 전 276/276/276에서 수정 후 276/50/140으로 바뀐다. `position_and_font`는 6/6/6인데, 이 책에서 교집합 후보가 이미 page당 1개 이하라 상한이 걸릴 대상이 없기 때문이며 무반응이 아니라 정상 동작이다.

## 검증

- `uv run pytest -q`: 432 passed. `uv run ruff check`, `uv run ruff format --check` 통과.
- 실제 PDF로 세 mode 모두에서 값을 0, 1, 3으로 바꿔가며 plan 항목 수 변화를 확인했다.
- `tests/test_heading_page_cap_modes.py`를 새로 추가해 상한 적용부가 mode 분기 뒤에 있고 `selected_ids`를 거르는지, font 전용 집합을 다시 좁히는 예전 구조로 되돌아가지 않았는지 검사한다.

## 대안과 제외한 선택지

- `position` mode에서 이 knob을 쓰면 config 오류를 내는 안은 배제했다. 사용자가 조합을 외우게 만드는 대신 knob이 일관되게 동작하는 편이 낫다.
- font 경로와 position 경로에 각각 다른 상한을 두는 안도 배제했다. 축이 늘어나면 agent가 탐색해야 할 공간만 커지고 해석성이 떨어진다.
- 문서에 "position mode에서는 효과가 없다"고 적고 두는 안은 배제했다. 문서가 아니라 동작이 계약이며, 이 저장소는 같은 이유로 이미 무반응 key를 제거했다.

## 남은 리스크

- 새 테스트는 구현 소스 텍스트를 검사해 적용 순서를 확인한다. 동작 자체가 아니라 구조를 보는 검사이므로, 함수를 크게 리팩터링하면 의미가 유지되더라도 실패할 수 있다. 대신 리팩터링이 이 함정을 다시 만들면 즉시 드러난다.
- `position_and_font` mode는 교집합이 이미 희소해 상한이 거의 바인딩하지 않는다. 이 mode에서 sweep을 돌리면 평평한 응답을 보게 되며, 그것은 knob이 죽은 것이 아니라 이 책에서 제약이 걸리지 않는다는 뜻이다.
