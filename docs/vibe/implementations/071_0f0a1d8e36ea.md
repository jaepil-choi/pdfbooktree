## 변경 배경

- 0.1.0 배포 전 library user가 설치 version, typed package 여부, 재현 가능한
  고수준 Python workflow와 run-owned artifact를 직접 사용할 수 있어야 했다.
- OCR 구현 dependency가 core install에 포함돼 일반 PDF 처리 사용자도
  `httpx`, `pikepdf`, `python-dotenv`를 설치해야 했고, CLI orchestration은 Python
  public API로 재사용할 수 없었다.
- 실험 110은 core/OCR extra metadata와 lazy failure 계약을, 실험 111은
  infer → preview → apply run과 canonical plan snapshot 계약을 검증했다.

## 결정 내용

- `pyproject.toml`을 version 단일 원천으로 유지하고 `_version.py`의
  `package_version()`과 `__version__`을 package root, CLI와 run manifest가
  공유하게 했다.
- `httpx`, `pikepdf`, `python-dotenv`를 `ocr` extra로 이동하고 `tqdm`은 일반
  처리에서도 쓰므로 core dependency에 유지했다.
- `OptionalDependencyError`가 extra 이름, 누락 distribution 목록과 설치 명령을
  구조화해 보존하도록 했다. OCR engine과 pikepdf insertion은 실제 실행 시점에만
  import한다.
- `workflows.py`에 `process_pdf`, `infer_pdf`, `preview_apply_plan`,
  `apply_plan_file`과 결과 모델을 추가하고 기본 CLI가 같은 orchestration에
  위임하게 했다. 기존 `Processor`와 단계형 함수, `--flat-output`은 호환
  저수준 경로로 유지했다.
- 기존 `artifact_paths`와 CLI JSON 직렬화 shape를 바꾸지 않고
  `ProcessingResult`에 typed path property를 추가했다.
- 모든 non-dry-run process/infer/apply 결과는 run root의
  `bookmark_plan.json`을 canonical snapshot으로 소유한다. 외부 apply plan은
  manifest `plan_source`에 원본 path와 SHA-256을 별도로 남긴다.
- `py.typed`와 `Typing :: Typed` classifier를 추가하고 repo-local skill과 package
  bundle의 공개 계약을 동일하게 유지했다.

## 작동 방식

- plain `ProcessingConfig`는 JSON 가능 데이터로 정규화한 뒤
  `sources=[{"kind": "python_api"}]`와 stable hash를 만든다. `ResolvedConfig`
  입력은 기존 source와 hash를 그대로 사용한다.
- 고수준 workflow는 input/config identity로 immutable run directory를 만들고
  manifest를 created → running → succeeded/failed로 갱신한 뒤 최종 manifest와
  `ProcessingResult`를 `ProcessingRunResult`에 함께 반환한다.
- `preview_apply_plan`은 PDF와 plan SHA-256, 1-based page 범위, bookmark 수,
  validation과 예상 output 경로만 계산하며 directory나 artifact를 만들지 않는다.
- core-only 환경에서도 package/OCR model import, 전체 help와 OCR batch dry-run은
  가능하다. 실제 single/batch OCR은 logger, output PDF나 artifact 생성 전에
  optional dependency preflight를 실행하고 CLI에서는
  `missing_optional_dependency`, exit 1로 변환한다.
- 기존 outline 재사용 시 `existing_outline_plan.json`은 원본 outline 근거로
  유지하고 별도의 canonical `bookmark_plan.json`을 생성한다.

## 대안과 제외한 선택지

- OCR package 전체를 core에 유지하는 선택은 일반 사용자의 설치 비용과 native
  wheel 의존성을 불필요하게 늘리므로 제외했다.
- `tqdm`까지 OCR extra로 이동하는 선택은 일반 batch/classification 진행 표시에도
  필요하므로 제외했다.
- CLI 전용 orchestration을 복제한 Python wrapper는 lifecycle과 artifact 계약이
  다시 어긋날 수 있어 제외하고 CLI와 public API가 같은 workflow를 사용하게 했다.
- `artifact_paths`를 typed dataclass로 교체하는 방식은 기존 JSON 계약을 깨므로
  mapping을 유지하고 property를 추가했다.
- OCR provider plugin 등록, cache/resume, doctor, encrypted PDF와 CI/publish
  workflow는 이번 구현 범위에서 제외했다.

## 남은 리스크

- Python 3.12와 Windows clean install은 검증했지만 Linux 원격 runner 성공 여부는
  별도 확인이 필요하다.
- live Upstage API 호출의 credential, rate limit과 비용은 기존 사용자 책임
  경계이며 clean install 검증에서는 네트워크 OCR 호출을 실행하지 않았다.
- package metadata version을 import 시점에 읽는 `__version__`은 설치 metadata가
  없는 source-only 실행에서 `0+unknown`으로 fallback한다.
- cache/resume, custom OCR provider 등록, encrypted PDF와 doctor interface는 후속
  범위다.
