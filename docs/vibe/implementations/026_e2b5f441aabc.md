## 변경 배경

- 기존 runtime TOC page detector는 `feature_vote_segment` 휴리스틱으로 목차 range를 골랐다. 031 실험에서 bookmark가 있는 PDF를 golden으로 두고 matching 성능을 확인했을 때, 휴리스틱 detector는 macro F1 0.4609 수준에 머물렀다.
- 005 계열 실험과 재학습 결과에서 pseudo label 기반 HistGradientBoosting classifier가 page-level TOC 재현 성능을 충분히 보였고, 사용자는 runtime detector가 이 ML 모델을 반드시 사용해야 한다고 요구했다.
- ML detector는 recall을 높이기 위해 range를 넓게 잡는 경향이 있었다. 그래서 후속 LLM 목차 추출 단계가 page별로 실제 목차 page인지 먼저 판단하고, 목차가 아닌 page는 skip해야 했다.

## 결정 내용

- `detect_toc_pages`의 runtime 구현을 학습된 joblib classifier 기반으로 교체했다. 기본 모델 경로는 `outputs/300study_toc_page_dataset_model/toc_page_dataset_model.joblib`이다.
- heuristic fallback은 의도적으로 제거했다. 모델 파일이 없거나 artifact의 feature schema가 현재 `TOC_PAGE_DATASET_FEATURE_NAMES`와 맞지 않으면 예외를 발생시켜, 처리 전에 반드시 train을 거치도록 강제한다.
- CLI `process` 명령에 `--toc-model-path`, `--toc-probability-threshold` 옵션을 추가했다. `train-toc-page-dataset`의 기본 모델은 `hist-gradient`로 바꿨다.
- LLM item extraction schema에 `is_toc_page`를 추가했다. basic extractor와 staged extractor 모두 LLM이 `is_toc_page=false`를 반환하면 해당 page의 item을 모두 버린다.
- `Processor`는 `ProcessingConfig.toc_detection`을 통해 ML detector 설정을 전달한다.

## 작동 방식

- PDF 앞부분 text에서 기존 `PageFeature`를 계산한 뒤, 현재 page feature와 직전 page feature를 학습 dataset과 같은 feature row로 변환한다. `page_position`에서 total page 수를 복원해 `total_pages` feature도 채운다.
- joblib artifact에서 `model`, `feature_names`, `training_summary`를 읽는다. feature 이름이 현재 코드와 다르면 조용히 보정하지 않고 실패한다.
- 모델의 `predict_proba` 결과가 threshold 이상인 page를 positive로 보고, gap 허용 연속 구간으로 묶은 뒤 probability mass가 가장 큰 segment를 TOC range로 고른다. page 번호는 기존 규칙대로 1-based를 유지한다.
- 탐지 결과의 method는 학습 report의 best model을 반영해 `ml_hist_gradient_toc_page_classifier`처럼 기록된다.
- LLM extraction은 page별 응답에서 `is_toc_page`를 먼저 본다. false이면 표지, 서문, 본문, `List of Pages`, 광고, 빈 page 등으로 판단된 것이므로 item 변환을 수행하지 않는다.

## 대안과 제외한 선택지

- ML artifact가 없을 때 기존 `feature_vote_segment`로 fallback하는 방안을 제외했다. 사용자가 runtime detector는 반드시 train된 모델을 사용해야 한다고 명시했고, fallback은 학습/배포 누락을 숨긴다.
- bookmark-guided detector를 runtime에 쓰는 방안도 제외했다. runtime 대상은 bookmark가 없는 PDF이므로, bookmark는 학습/평가용 pseudo label 또는 golden reference로만 사용한다.
- ML detector threshold를 높여 precision을 직접 올리는 방식은 이번 커밋의 주된 해결책으로 삼지 않았다. range detector는 recall 쪽을 확보하고, page별 LLM gate가 비목차 page를 제거하는 책임을 갖는 쪽이 역할 분리가 더 명확하다.

## 남은 리스크

- 학습 label은 bookmark-guided pseudo label이므로 독립 수동 검수 ground truth가 아니다. 모델 성능 수치는 pseudo label 재현 성능으로 해석해야 한다.
- ML detector가 range를 넓게 잡는 경향은 여전히 있다. 031 재실험에서 `is_toc_page` gate 이후 macro F1은 0.7230으로 개선됐지만, 일부 책에서는 LLM gate가 실제 목차 page까지 false 처리할 수 있다.
- default model artifact는 `outputs/` 아래에 있으며, 배포/사용 환경에서 이 artifact가 없으면 runtime은 실패한다. 향후 모델 artifact 관리 정책을 명확히 해야 한다.
