## 변경 배경

- 기존 `LlmTocRangeReviewer`는 experiment 016의 3단계 fallback(start accept /
  backtrack_start / sequential recovery)을 옮긴 것이었다. LLM이 page별로
  `is_toc_start`(목차 시작 page 여부)까지 판정하게 했는데, 시작 경계 판정을 LLM에
  맡기는 부분이 흔들림의 원인이었다.
- experiment 038(full flow)에서 검증한 per-page 보정 흐름이 더 단순하고 견고했다.
  핵심 차이는 (1) 목차의 **필수 요건으로 본문 페이지 번호 동반**을 요구하고,
  (2) 시작/끝 경계 판정을 LLM이 아니라 코드의 양방향 확장이 결정한다는 점이다.
- 사용자와 합의한 방향: anchor 결정을 038식 forward 스캔으로 교체하고,
  `has_page_numbers` gate는 항상 강제한다.

## 결정 내용

- LLM 응답 스키마를 `is_toc_page` / `is_toc_start` / `reason`에서
  `is_toc_page` / `has_page_numbers` / `confidence` / `reason`으로 교체했다.
  `is_toc_start`를 제거하고 `has_page_numbers`를 추가했다.
- 수락 조건을 항상 `is_toc_page AND has_page_numbers`로 못 박았다(`_is_accepted`).
  페이지 번호 없이 제목·주소·메모만 나열한 목록(예: 본문 페이지 번호 없는 Brief
  Contents)은 목차로 보지 않는다. 토글은 두지 않았다(사용자 결정: 항상 강제).
- anchor 탐색을 3단계 fallback 대신 단일 경로로 단순화했다. detector start(seed)부터
  앞으로 `max_anchor_scan`(기본 20) page까지 스캔해 첫 수락 page를 anchor로 잡는다.
  seed가 없으면 page 1부터 스캔한다.
- 양방향 확장의 gap 정책을 비대칭으로 두었다. forward는 `forward_gap_tolerance`
  (기본 2)만큼 연속 non-TOC page를 관용해 스캔 OCR 책의 중간 오판을 건너뛰고,
  backward는 brief contents 오염을 막으려고 관용 없이 첫 non-TOC에서 멈춘다.
- `LlmRangeReviewConfig`에서 `max_sequential`/`end_gap_tolerance`를 제거하고
  `max_anchor_scan`/`forward_gap_tolerance`를 추가했다. `prompt_max_chars` 기본값을
  038과 맞춰 4500→2500으로 낮췄다.
- system prompt(`DEFAULT_TOC_RANGE_REVIEW_SYSTEM_PROMPT`)를 038의 per-page 프롬프트로
  교체했다(halt 판단 금지, 페이지 번호 필수 요건 명시).

## 작동 방식

- `Processor`는 `use_llm=True`일 때만 `detect_toc_pages`(ML) 결과를
  `LlmTocRangeReviewer.review()`에 넘긴다. reviewer는 앞부분 `scan_pages` page의
  text를 미리 확보한 뒤 `_ReviewState`로 per-page 판정을 돌린다.
- `_ReviewState.probe`는 page text snippet(`prompt_max_chars`까지)을 LLM에 보내
  판정을 캐시하고 trace에 남긴다. 빈 page는 LLM 호출 없이 비-목차로 처리한다.
- `find_anchor` → `grow_block` 순서로 range를 정한다. anchor를 못 찾으면
  stage=`no_toc_range`, 찾으면 stage=`forward_scan`으로 `TocRangeReview`를 돌린다.
  method는 `llm_perpage_scan`이다.
- page는 모두 1-based PDF page다. `_probe_call`의 user prompt 형식은 experiment
  038에서 검증한 형식을 그대로 쓴다. (군더더기 마커를 붙이면 OCR이 심하게 깨진 경계
  page 판정이 흔들리는 것을 showcase 008에서 확인했다 — kim_note1 page 3.)

## 대안과 제외한 선택지

- "3-stage 유지 + gate만 강화": 변경 최소화 안이었으나 `is_toc_start`를 남기면
  시작 경계 판정을 LLM에 맡기는 약점이 그대로 남아 제외했다(사용자 결정: forward
  스캔 교체).
- "has_page_numbers config 토글": 강의노트류(번호 없는 목차) 대응 여지를 남기는
  안이었으나 사용자 결정으로 항상 강제했다.
- "experiment 016 그대로 유지": 038이 더 단순하고 precision이 안정적이라 폐기했다.

## 남은 리스크

- `has_page_numbers` 항상 강제는 알려진 trade-off를 들여온다: 페이지 번호가 거의
  없는 강의노트 목차(kim_note2 page 8-10)는 누락된다. 필요 시 config 토글로 완화할
  여지를 코드 구조상 남겨두었다(현재는 강제).
- 경계 page 판정은 OCR 품질과 LLM 변동성에 민감하다. user prompt 형식을 038과
  동일하게 맞춰 안정화했으나, 심하게 깨진 스캔본에서는 여전히 흔들릴 수 있다.
- `Processor`의 use_llm 기본값은 False라 평상시 동작은 바뀌지 않는다. live 회귀는
  showcase로만 커버되고 단위 테스트는 fake client로 격리 검증한다.
