## 변경 배경

- Phase 7 1차 증분에서 `batch`의 공통 result/error/event와 versioned config
  계약은 적용했지만, 각 PDF는 여전히 `output/<stem>`에서 직접 실행돼
  `run_id`, config hash, 실패 manifest가 남지 않았다(구현 노트 058의 잔여 리스크).
- 단일 `process`와 같은 재현성·감사 가능성을 batch item에도 적용하고, batch
  summary에서 각 item의 실제 run과 output을 따라갈 수 있어야 했다.

## 결정 내용

- 기존 `ProcessingResult`를 상속하는 공개 `BatchItemResult`를 추가하고
  `run_id`/`run_dir`/`manifest_path`/`config_hash`를 평면형 필드로 덧붙였다.
  기존 batch item의 `status`/output 필드 shape는 유지한다.
- `BatchProcessor`는 `ProcessingConfig | ResolvedConfig | None`을 받는다. CLI는
  config source까지 보존된 `ResolvedConfig`를 전달하고, Python API의
  `ProcessingConfig`는 `python_api` source와 stable hash를 가진 identity로 만든다.
- 각 PDF에 `create_run_context()`를 적용한다. 손상 PDF도 failed manifest를
  남길 수 있도록 batch에서만 `allow_unreadable_input=True`를 사용하고,
  읽을 수 없는 input의 `page_count`는 `null`로 기록한다.
- 파일별 실패는 기존 계약대로 batch를 중단하지 않고 exit 0 +
  `failed_count`로 반환한다.

## 작동 방식

- `BatchProcessor._run_one()`이 input/config identity로 run directory와 created
  manifest를 만들고 `start()`로 running 상태를 기록한다.
- `Processor`는 해당 `run_dir` 안에서 실행된다. 반환 결과는 `complete()`가
  output/artifact/report/warning과 최종 processing status를 manifest에 연결한다.
- 처리 예외나 손상 PDF는 `fail()`이 오류 type/message와 finished 시각을 남긴다.
  이후 기존 `ProcessingResult` 필드와 run identity를 합친 `BatchItemResult`를
  batch summary의 `results`에 넣는다.
- run identity 자체를 만들기 전의 hash 읽기·directory 생성 같은 infrastructure
  실패에서는 run 필드가 `null`인 failed item을 반환한다.

## 대안과 제외한 선택지

- run 필드를 `ProcessingResult` 자체에 추가하면 `process`/`infer`/`apply` 등 모든
  command JSON에 무관한 null 필드가 생겨 제외했다. 별도 wrapper의 `result`
  하위에 중첩하는 방식도 기존 batch item shape를 깨므로 상속 기반 평면 확장을
  선택했다.
- run lifecycle을 batch CLI에만 두는 방식은 Python `BatchProcessor` 소비자가
  재현 정보를 얻지 못하므로 제외했다.
- 손상 PDF를 run 생성 전에 즉시 실패시키는 기존 동작은 실패 item의 manifest가
  사라지므로, 명시적 opt-in에서만 unreadable identity를 허용했다.

## 남은 리스크

- input hash를 읽지 못하거나 output run directory를 만들 수 없는 infrastructure
  실패는 identity 자체를 만들 수 없어 run 필드가 null이다.
- item manifest는 연결됐지만 batch 전체 실행을 나타내는 별도 durable manifest나
  summary artifact는 아직 없다. 현재 batch summary는 CLI result envelope다.
- `ocr_policy` 실제 연결과 README/artifact/exit-code 문서화는 Phase 7 잔여
  범위로 남아 있다.
