## 변경 배경

- font size만으로 heading을 고르면 수식, 그림, OCR 조각의 불규칙한 크기가 후보에 섞였다. 여러 page에서 같은 top-left anchor pattern이 반복되는지를 독립 신호로 사용하고, font 후보와 정확한 chunk 단위로 교차할 필요가 있었다.
- 실험 `096_min5_text_coverage_font_tiers`에서 Investments PDF를 비교한 결과, 기존 자동 position tolerance의 AND F1은 0.5217이었고 본문 top-to-top median line spacing을 tolerance로 사용하면 0.6719로 높아졌다. `line spacing - font size`인 2.5pt는 F1 0.2895로 지나치게 엄격했다.
- 실제 OCR overlay 책에서는 기존 sparse-merged font tier가 통계학원론의 font를 두 tier로만 합쳐 95% 누적 규칙이 모든 tier를 본문으로 흡수했다. 실험의 강건한 density valley tier를 production에서도 보존해야 했다.
- Markdown split은 어떤 bookmark level도 10,000단어 이하 95% coverage를 만족하지 못하면 파일을 하나도 만들지 않았다. 사용자는 추가 page/word 분할 없이 가장 깊은 level을 그대로 export하는 명시적 fallback을 요구했다.

## 결정 내용

- `TypographyConfig`에 `heading_candidate_mode`, `body_font_text_coverage`, `position_min_repeated_pages`를 공개 설정으로 추가했다. 기본 모드는 `position_and_font`, coverage는 0.95, 최소 반복은 서로 다른 5개 page다.
- OCR 조각을 같은 인쇄 line으로 복원한 뒤 본문 line spacing으로 paragraph/title chunk를 만들고, 현재 chunk와 다음 chunk의 top-left 좌표 네 개를 position pattern으로 사용한다.
- position 좌표는 본문 top-to-top median line spacing으로 정규화하고, cluster의 좌표별 `max - min <= 1.0`을 허용 범위로 정했다. 병합된 heading은 첫 chunk의 anchor를 유지한다.
- font tier는 sparse merge하지 않고 강건한 Silverman bandwidth KDE의 density valley를 그대로 보존한다. tier별 공백 제외 text length를 큰 순서로 누적해 95%를 처음 넘기는 tier 전체까지 본문으로 분류한다.
- position과 font 결과는 동일 `chunk_id`의 교집합으로 AND한다. 선택 근거와 line-spacing tolerance는 heading evidence에 기록한다.
- `export/fallback.py`를 별도 모듈로 만들고 coverage를 만족하는 level이 없을 때 문서가 존재하는 가장 깊은 level을 선택한다. 추가 page/word 분할은 하지 않는다.
- fallback export에서도 `constraint_satisfied`는 실제 coverage 결과인 `False`를 유지한다. 대신 `fallback_used`, `fallback_reason`, `chosen_level`, overflow 통계를 public result와 manifest에 명시한다.

## 작동 방식

- `Processor`는 margin artifact를 제외한 line으로 geometry 전용 font tier를 계산하고 `extract_geometry_headings`를 호출한다. 결과 heading은 기존 font-tier stack outline 추론에 들어가므로 PDF bookmark와 Markdown 경로는 기존 public interface를 유지한다.
- 본문 line spacing은 본문 tier line의 같은 page, 겹치는 가로 영역, 양의 top-to-top 거리만으로 계산한다. density band 상한은 line을 chunk로 이어 붙이는 기준이고 median spacing 한 칸은 page 간 anchor pattern tolerance다.
- Markdown split은 L1부터 가장 깊은 level까지 coverage를 계산해 처음 만족한 level을 선택한다. 아무 level도 만족하지 못하면 fallback 모듈이 가장 깊은 level을 반환하며 해당 level의 모든 문서를 저장한다.
- `MarkdownExportResult`와 manifest는 정상 선택과 fallback 선택을 구분한다. fallback 파일 중 `max_words`를 넘는 문서는 `overflow_files`에 그대로 보고한다.

## 대안과 제외한 선택지

- 고정 pt나 font size 비율 tolerance는 책마다 typography 단위가 달라 제외했다.
- 다른 page 최근접 pattern 거리 중앙값은 Investments에서 6.79pt로 추론되어 recall이 낮았으므로 선택하지 않았다.
- `line spacing - font size`는 2.5pt로 지나치게 엄격해 후보가 195개, recall이 0.1803까지 떨어져 제외했다.
- fallback에서 PDF page 경계 또는 word 수로 추가 분할하는 방식은 사용자 요구에 따라 구현하지 않았다.
- coverage 실패를 성공으로 표시하지 않았다. export 수행 여부와 목표 충족 여부를 별도 상태로 유지했다.

## 남은 리스크

- OCR layout이 불안정한 통계학원론은 position AND font 결과에도 수식과 본문성 문장이 일부 bookmark로 남는다. fallback은 export 가용성만 보장하며 outline 품질을 보정하지 않는다.
- density valley 수가 많은 책에서는 font tier가 과도하게 세분화될 수 있다. 여러 OCR/native 책에서 후보 precision과 실행 시간을 계속 관찰해야 한다.
- position pattern clustering은 책 전체 pattern 수에 따라 계산량이 증가한다. 대규모 책에서 공간 index나 bucket 기반 최적화가 필요할 수 있다.
- fallback 결과에는 10,000단어를 넘는 파일이 남을 수 있으며, 이는 `constraint_satisfied=False`와 `overflow_files`로만 전달된다.
