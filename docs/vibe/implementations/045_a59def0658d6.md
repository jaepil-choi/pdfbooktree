## 변경 배경

- 이 라이브러리의 실전 처리 대상은 사실상 전부 scanned/OCR 문서다.
  `Processor.run()`은 이미 embedded outline이 있으면 typography 추론을
  건너뛰므로(`skip_existing_bookmarks`), typography 추론 경로에 실제로
  들어오는 문서는 "쓸 만한 bookmark가 없는" 문서뿐이고, 그런 문서는 거의
  전부 scanned/OCR이다. native/clean PDF는 보통 embedded bookmark를
  갖고 있어 애초에 이 경로의 대상이 아니다.
- 그런데 production 기본값 `heading_candidate_mode="position_and_font"`는
  position 후보와 font 후보의 교집합(AND)만 인정한다. 실험 098(통계학원론
  OCR)에서 chapter 제목 font가 본문 font tier에 완전히 흡수되는 경우
  (`chapter_font_candidate_count=0`) AND 게이트는 chapter를 11개 중
  0개도 복구하지 못했다.
- 실험 097(Investments, native gold 비교)은 font ranking에 position
  support/isolation을 결합하면 chapter 탐지가 AP=1.0까지 올라간다는 것을,
  실험 098은 font tier가 아예 없을 때 current-anchor 2D(4D보다 우월,
  11/11 vs 7/11) + support/isolation cluster가 유일한 단서라는 것을,
  실험 099는 position isolation이 "bookmark 존재 신호"이지 "level(계층
  깊이) 신호"는 아니라는 것을, 실험 100은 이 fallback을 font 골격에 그냥
  더하면 native 문서에서는 precision이 오히려 떨어진다는 것을(0.63→0.63/
  0.57, 0.45→0.45/0.34), 실험 101은 같은 알고리즘을 실제 scanned 책 3권에
  적용한 결과를 검증했다. 이 커밋은 097~101에서 수렴한 결론
  ("font 골격 + body-tier position fallback을 font parent range+1로
  삽입")을 production 코드로 옮긴 것이다.

## 결정 내용

- `heading_candidate_mode` 기본값을 `position_and_font`(AND) →
  `font`로 바꿨다. AND 게이트는 실전 대상 문서에서 이미 실패가 증명된
  경로이므로 더 이상 기본값일 이유가 없다. `position`/`position_and_font`는
  비교·디버깅용으로 남겼다.
- font 골격 후보 조건에 `font_size > representative_body_font_size`와
  `word_count <= body_font_max_words`(기본 20)를 추가했다. 기존 "font"
  모드는 tier membership만 봐서 본문보다 작은 tier(각주 등)나 긴 강조
  단락까지 후보로 끌어왔는데, 실험 100/101이 검증한 조건으로 좁혔다.
- 새 knob은 모두 `TypographyConfig`에 추가하고 CLI에도 노출했다:
  `body_font_max_words`, `position_fallback_enabled`,
  `position_fallback_tolerance`, `position_fallback_min_isolation_ratio`,
  `position_fallback_body_font_ratio_low/high`,
  `position_fallback_title_dedupe_threshold`.
- scanned/OCR 여부를 판정해서 fallback을 켜고 끄는 분기는 만들지 않았다.
  위 "변경 배경"에서 설명한 대로 이 경로에 도달하는 문서는 이미 사실상
  전부 fallback이 필요한 문서이기 때문이다(사용자 피드백으로 이전 설계의
  `classify_scan` 게이트를 제거함). native 문서에 대한 실험 100의 우려는
  "production에서 이 fallback이 켜질 일이 없는 문서"에 대한 것이었으므로
  런타임 분기가 아니라 설계 근거로만 남았다.
- position fallback 후보는 level을 스스로 정하지 않는다
  (`typography/position_fallback.py`는 후보 탐색만 하고,
  `outline/plan.py::insert_position_fallback`이 level을 정한다). 실험
  100의 결론("page-range parent 삽입은 precision gate가 아니라 순수
  level 결정 방식") 때문에 두 책임을 분리했다.

## 작동 방식

1. `typography/geometry.py::build_geometry_context`가 chunk 분할·
   font coverage profile·본문 line spacing을 한 번만 계산해
   `GeometryContext`로 반환한다. `extract_geometry_headings`(font 골격)와
   `select_body_tier_position_fallback`(fallback)이 이 context를 공유해서
   같은 계산을 두 번 하지 않는다.
2. `select_geometry_headings`가 font 골격 후보를 뽑고
   (`heading_candidate_mode` 기본값 `font`),
   `infer_bpe_outline` + `normalize_bookmark_plan`으로 `font_plan`을
   만든다.
3. `select_body_tier_position_fallback`이 `current_anchor_2d` 패턴
   (`_build_anchor_patterns(..., pattern_mode="current_anchor_2d")`,
   tolerance=2.0)으로 chunk를 클러스터링하고, cluster별 distinct-page
   지지도(`support_pages`)와 가장 가까운 다른 cluster로부터의 L-inf
   isolation ratio를 계산한다. 물리 line 1개, body tier 소속,
   대표 본문 폰트 ±3%, support>=5, isolation>=1.0인 chunk만 후보로 남기고,
   같은 page의 font 골격 title과 유사도(`normalize_for_match` +
   SequenceMatcher/token overlap) 0.8 이상이면 중복으로 스킵한다.
4. `outline/plan.py::insert_position_fallback`이 `font_plan`의 각
   항목의 page range를 구해서(`_plan_ranges`, `outline/tree.py`의
   `_end_page`와 동일한 nesting 규칙), 후보 page를 포함하는 가장 깊은
   range를 부모로 골라(`_deepest_parent`) `level = parent.level + 1`을
   배정한다. 부모가 없는(= font 골격이 아예 비어 있어 어디에도 못 붙는)
   후보는 버린다. 병합은 `(pdf_page, font/position 여부)` 기준 안정
   정렬로 하는데, `BookmarkPlanItem`이 y0를 안 갖고 있어 page 단위보다
   세밀한 정렬은 못하지만, `_deepest_parent`가 항상 가장 안쪽 range를
   고르기 때문에 이 정도로도 `outline/tree.py::build_outline_tree`의
   stack 기반 parent-child 추론이 정확히 유지된다(page range가 서로
   포함관계로만 중첩되고 교차하지 않는다는 불변식에 의존).
5. `Processor.run()`은 `position_fallback_enabled`(기본 True)일 때만
   3~4단계를 수행하고, 병합한 plan을 `normalize_bookmark_plan`으로 다시
   정리해 이후 파이프라인(BPE, export)에 그대로 흘려보낸다.
   `position_fallback_candidates` artifact를 새로 기록한다.

## 대안과 제외한 선택지

- **scanned/OCR 판정으로 fallback on/off를 분기하는 설계**를 먼저
  제안했지만 기각했다. `skip_existing_bookmarks`가 이미 "쓸 만한
  bookmark 없는 문서"만 이 경로로 보내고, 그런 문서는 실전에서 전부
  scanned/OCR이므로 분기 자체가 불필요한 복잡도였다.
- **font tier 스택으로 fallback level을 정하는 방식**은 쓰지 않았다.
  fallback 후보는 정의상 body tier(= 본문과 같은 tier)이므로 font tier
  스택에 넣으면 항상 level 1로 쌓이거나 본문과 구분이 안 된다. 실험 100이
  검증한 "가장 깊은 font parent range + 1" 방식만 사용했다.
- **support/isolation hard threshold를 ranking 방식으로 바꾸는 것**
  (실험 097이 native 책에서 AP=1.0을 낸 font_plus_support/isolation
  ranking)은 이번 커밋에 포함하지 않았다. 097 자체가 이 threshold를
  `same_book_exploratory`로 명시했고, 지금 구현은 101이 실제 3권에서
  재현 가능함을 보인 hard threshold(support>=5, isolation>=1.0, ±3%)만
  옮겼다.

## 남은 리스크

- `position_fallback_body_font_ratio_low/high=(0.97, 1.03)`,
  `position_fallback_tolerance=2.0` 같은 threshold는 실험 097~101에서
  검증한 책 몇 권(Investments, 퀀트의 세계, 금리의 경제학, 통계학원론,
  한경 읽는법)에 한정된 값이다. 다른 책에서는 재조정이 필요할 수 있다.
- `BookmarkPlanItem`이 y0를 보존하지 않아서, 같은 page에 font 항목과
  fallback 후보가 여러 개 있을 때 정확한 등장 순서를 보장하지 못한다.
  지금은 "font 항목을 먼저, 그다음 fallback을 y0 순으로" 배치하는 근사
  규칙만 쓴다. 실제 3권 showcase에서는 문제가 드러나지 않았지만, 한 page에
  fallback 후보가 여러 개 몰리는 책에서는 순서가 어긋날 수 있다.
- 통계학원론처럼 OCR이 수식/표를 큰 글자로 잘못 인식하는 책은 여전히
  font 골격 자체가 오염된다(`\begin{array}...` 같은 LaTeX 조각이 L1로
  들어감). 이건 이번 커밋의 범위가 아니라 OCR/font tiering 쪽의 별도
  문제다.
