## 변경 배경

- page 단독 feature만으로는 목차처럼 보이는 일반 본문 page와 실제 TOC page를 구분하기 어렵다.
- 사용자는 모델이 `t-1` 시점의 page feature를 함께 보게 하여, 직전 page까지의 흐름을 기준으로 현재 page의 TOC 여부를 맞추도록 요구했다.
- 005/006 실험에서 직전 page feature를 추가한 모델이 structural-only 모델보다 F1, ROC-AUC, average precision을 개선했다.

## 결정 내용

- `TocPageDatasetRow`에 `prev_*` feature column을 추가했다.
- 현재 page feature 구조인 `PageFeature` 자체에는 직전 page 정보를 넣지 않고, 학습 dataset row에만 결합했다.
- positive/negative sample을 만들 때 현재 page의 바로 앞 1-based PDF page인 `pdf_page - 1`의 구조 feature를 함께 추출한다.
- 이전 page가 없거나 추출되지 않은 경우 `prev_page_available=False`와 `None` 값을 기록한다.
- class 기반 batch detector와 함수형 `_build_dataset_rows()` 경로가 같은 column을 만들도록 양쪽을 함께 수정했다.

## 작동 방식

- bookmark-guided detection 결과에서 positive page와 negative sample page를 정한 뒤, 각 sample의 `pdf_page - 1`을 추가 추출 대상에 포함한다.
- `calculate_page_features()`로 현재 page와 이전 page 후보의 구조 feature를 같은 방식으로 계산한다.
- dataset row 생성 시 `feature_by_page.get(pdf_page - 1)`를 `previous_feature`로 넘긴다.
- `previous_feature`가 있으면 line count, word count, final-number pattern, TOC keyword 여부 등 현재 page와 대응되는 구조 feature를 `prev_*` column에 기록한다.
- 이 정보는 이전 page의 텍스트와 구조에서 계산된 feature일 뿐 정답 label을 쓰지 않으므로, 순차 추론 시점에서 사용할 수 있는 문맥 feature다.

## 대안과 제외한 선택지

- `PageFeature`에 이전 page feature를 중첩하는 방식은 단일 page feature의 의미를 흐리므로 제외했다.
- `t+1` feature는 현재 page 판정 시 뒤 page까지 봐야 하므로 온라인 추론 제약이 커져 이번 범위에서 제외했다.
- 이전 page label이나 detector 결과를 feature로 쓰는 방식은 label leakage와 파이프라인 순환 의존 위험이 있어 제외했다.

## 남은 리스크

- PDF 첫 page 또는 추출 실패 page는 `prev_*` 값이 비어 있으므로 모델이 결측 처리 전략에 의존한다.
- 직전 page가 본문이지만 현재 page가 목차처럼 보이는 특수 layout에서는 t-1 feature가 오히려 약한 부정 신호가 될 수 있다.
- 향후 모델 inference API를 만들 때 학습과 동일한 `prev_*` column 순서와 결측 표현을 보장해야 한다.
